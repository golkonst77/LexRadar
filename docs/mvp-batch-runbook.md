Resume — та же команда с `--resume`; неизменность CSV, параметров и результатов обязательна.

## Дополнительная защита production GO

DEMO остаётся явно синтетическим. В paid/saved даже полностью подтверждённой
цитаты недостаточно: без независимого юридического разбора получается HOLD
`independent_legal_review_required`, клиентского HTML нет. Нормы от AI не считаются проверенными.
Если сами факты не проходят действующие критерии, ручной разбор не отменяет этот отказ.

После аудита в каталоге сайта лежит незаполненный `legal-review-template.json`.
Юрист создаёт отдельный файл на его основе, оставляя точные packet_sha256 и
analysis_sha256, указывает reviewer и фактическое reviewed_at с часовым поясом.
Каждый элемент findings должен содержать:

```json
{
  "finding_id": "ТОЧНЫЙ_ID_НАХОДКИ",
  "factual_defect_verified": false,
  "legal_applicability_verified": false,
  "serviceable": false,
  "reason": "Содержательное обоснование факта, применимости и предлагаемой работы",
  "verified_legal_sources": ["Реквизиты и источник независимо проверенной действующей нормы"]
}
```

Все три true допустимы только после независимой проверки; текст AI не заменяет её.
Добавьте колонку `legal_review` с абсолютным путём в CSV **saved**, затем выполните
saved-команду в новом каталоге. Это позволяет подготовить GO без повторного платного
аудита. В HTML попадут только находки, допущенные и технической, и юридической проверкой.
Файл является заявлением проверяющего, а не криптографически удостоверенной подписью.
Права локальной файловой системы и реальная квалификация проверяющего остаются
ответственностью оператора. Автоматическая проверка законодательства не реализована.

## Самый короткий операторский путь

1. Демонстрация: команда mvp_demo ниже (новый output).
2. Реальный сохранённый результат: команда saved_audit выше, без разрешений и расходов.
3. Собственный небольшой CSV: образцы `docs/examples/mvp-066-leads.csv` и
   `docs/examples/mvp-066-one-local.csv`. Примерные домены и пути замените своими.
4. После отдельного разрешения на сбор — prepare-команда ниже. Затем человек
   проверяет каждый packet.json и отдельно одобряет точный SHA и внешнюю передачу.
5. После разрешения на бюджет — paid-команда ниже, **один сайт**, max-ai-calls=1,
   max-total-budget-usd=0.50. Она обрабатывает готовое dossier; collect и AI разделены
   проверкой пакета. Без разрешений выводится NEEDS_APPROVAL до платного вызова.
6. Посмотрите results.csv: ошибка строки не останавливает остальные строки.
   Подготовка нескольких пакетов разрешена; массовый paid для нескольких сайтов BLOCKED.
   Approval одного сайта не применяется к другим. Завершённые результаты можно
   перечитать той же командой с --resume, без повторного расхода.

## Входной CSV

Загрузить означает сохранить файл локально и передать его путь CLI:

```csv
url,company_name,email
https://company.example/,ООО Компания,contact@company.example
https://another.example/,ИП Пример,
```

Обязательны заголовки `url,company_name,email`, значения company_name/email могут быть
пустыми; пустой URL — ERROR. Поддержаны UTF-8 и UTF-8 BOM, `,` и `;`, quoted values,
дополнительные поля. Дополнительные поля сохраняются в `manifest.json` → `rows[].input`.
Почта — только локальные данные, нигде не отправляется и в AI-пакет не включается.
Дубли определяются по каноническому URL (включая устранение fragment), первый имеет
приоритет; разные страницы одного домена не объединяются. Ошибка количества колонок
или URL изолируется в строке; синтаксически разрушенный CSV, например незакрытая
кавычка до конца файла, отклоняется целиком до начала работы.

## Аудит одного реального сайта: отдельное разрешение и approval

Нельзя использовать массовый CSV как разрешение массовых AI-запросов.
Выберите **одну** строку со свежим корректным досье, сохраните её как
`runs/operator-one.csv` с колонками url,company_name,email,dossier.
Не берите DEMO-досье. Проверьте пакет локально и создайте approval только после
его человеческой проверки. Формат действующего контракта:

```json
{
  "packet_sha256": "ТОЧНЫЙ_SHA256_PAYLOAD_ИЗ_PACKET_JSON",
  "approved": false,
  "contents_reviewed": false,
  "reviewer": "",
  "approved_at": "ФАКТИЧЕСКОЕ_ВРЕМЯ_С_ЧАСОВЫМ_ПОЯСОМ"
}
```

Это незаполненный образец, не действующее разрешение. Оператор после проверки
сам заполняет reviewer/time и оба true. SHA связан с содержимым конкретного пакета;
старое разрешение другого пакета не подходит. Screening включён по умолчанию.
Если он блокирует данные, сначала проверьте/обезличьте материалы и переподтвердите
новый SHA. Только осознанное отдельное решение позволяет добавить
`--mvp-no-screening`: это выключает screening, но сохраняет все проверки approval/SHA.

После отдельного разрешения на передачу через OpenRouter в DeepSeek и расход до $0.50,
при штатно настроенном окружении провайдера (значение ключа не выводить):

```bash
PYTHONPATH=src /tmp/lexradar-029-venv/bin/python -m lexradar.mvp_batch runs/operator-one.csv \
  --output runs/operator-paid-001 --mode paid --max-sites 1 \
  --allow-paid-single --allow-external-transfer --max-ai-calls 1 \
  --max-total-budget-usd 0.50 --timeout-seconds 120 \
  --packet-approval runs/operator-one-approval.json
```

Модель `deepseek/deepseek-chat`, только A; B/Qwen не вызывается. Профиль и транспорт
существующего Single A сохранены: timeout 45 секунд по умолчанию (120 в команде выше), retry 1, 4000 output tokens,
price caps $1/$2 за миллион, общий бюджет $0.50 с резервами перед попытками,
200000 input bytes, 500000 response bytes, no fallback. В runs-064 сохранён успешный реальный ответ этой модели с timeout 120 секунд;
это исторический факт, а не гарантия следующего вызова. В задании 66 новых вызовов нет.
Нет фиктивной подстановки при ошибке или timeout. По умолчанию max-ai-calls=1:
повторный транспортный вызов блокируется, даже если внутренний retry разрешён.
Явное max-ai-calls=2 допускает второй запрос в пределах того же общего бюджета.
Неизвестный расход удерживает консервативный резерв; максимум общего лимита $0.50.
Следующий сайт требует нового одно-сайтового CSV, нового каталога и отдельной
проверки/approval его пакета. Автоматического массового платного режима нет.

## Результаты и расходы

- `results.csv`: SUCCESS/ERROR/SKIPPED — выполнение; отдельная qualification GO/HOLD —
  коммерческий отбор; reason — диагностика. GO требует пригодного факта и, в production, независимого юридического разбора;
  это коммерческий отбор, а не судебное установление нарушения.
- `manifest.json`: оригинальные дополнительные CSV-поля, stages, сводки,
  SHA всех файлов попытки; `automatic_send_allowed=false`, `client_release_allowed=false`.
- `sites/.../analysis/analysis.json`, `requests.jsonl`: результат A, попытки,
  request_sent, usage и безопасная диагностика. `run.json` сохраняется orchestrator.
- `cost_usd`: сумма известных usage.cost_usd; если хотя бы одно значение неизвестно
  в paid, поле `unknown`. `cost_known=false` означает необходимость сверки с провайдером.
  `budget_charge_usd` — консервативный учёт бюджета, не обязательно фактическое списание.
  После ранней ошибки до inference эти поля могут отсутствовать; смотрите наличие analysis.
- HTML находится по относительному пути из колонки `proposal`. Только GO создаёт
  `proposal.html`. HOLD/ERROR не создают клиентского предложения. Содержимое —
  проверенные точные цитаты, компания и домен, отдельно обозначенный правовой риск.
  Законы, штрафы и интерпретации AI в HTML не переносятся без независимой проверки.
- Услуга ИП Голубева: документы + методичка вебмастеру; исправления сайта только
  по отдельному согласованию. Первичный аудит бесплатный.

Локальный HTML — проект для проверки человеком, а не разрешение его отправить.
Отправка, интеграция email и автоматическая рассылка отсутствуют.

## Возобновление

Офлайн-демо (не запускайте генератор повторно в существующий каталог):

```bash
env -u OPENROUTER_API_KEY PYTHONPATH=src /tmp/lexradar-029-venv/bin/python \
  -m lexradar.mvp_batch /tmp/lexradar-063-operator-demo/DEMO-inputs/input.csv \
  --output /tmp/lexradar-063-operator-demo/DEMO-results --max-sites 5 --resume
```

Для prepare повторите исходную prepare-команду с `--resume` и теми же флагами.
CSV (включая байты), режим и лимит должны совпадать. Завершённые SUCCESS/ERROR/SKIPPED
не повторяются. Прерванные pending продолжаются в новом retry-каталоге, старый
сохраняется. Изменённые файлы завершённой попытки блокируют resume по SHA.
Лимит считает уникальные попытанные строки; для увеличения лимита нужен новый output.
Для повторной обработки ERROR сформируйте новый CSV и новый output.

**Paid resume** с завершёнными строками безопасно перечитывает результат без AI.
Если прерывание оставило pending с каталогом попытки, resume запрещён до ручной
сверки журналов и расхода. Не запускайте такую строку в новом output без отдельного
решения: новый каталог сам по себе не исключает повторного списания.
`paid-attempt.json` записывает резерв до обращения к провайдеру.
NEEDS_APPROVAL/ERROR/SKIPPED не повторяются через resume. Параллельный запуск
в один output блокируется file lock; устаревшее состояние после захвата lock отклоняется.

Каталог назначения должен быть новым. Передать в ChatGPT вручную только

передачи персональных данных. Автоматической передачи нет. Экспорт закрыт правами
0700/0600 и исключён из Git. Для другого сохранённого аудита без provenance указать
`--dossier <каталог-досье>`. Будущие аудиты содержат `capture-A-<попытка>`:
точный текст сообщения модели до валидации, фактический системный промпт, пакет,
статус и отметку редактирования секретов. Служебные HTTP-заголовки не сохраняются.

В запуске 064 исходный ответ не сохранялся. `ORIGINAL_NOT_AVAILABLE` означает
реальную утрату оригинала, а не пустой ответ модели. Нормализованный анализ
экспортируется отдельно. Промпт и пакет восстанавливаются только при совпадении
хешей. Ошибка транспорта может означать отсутствие полученного текста; экспортёр
не выдумывает его. HTML содержит все находки, точные доступные цитаты, оценку
доказательств и причины квалификации. GO/HOLD — оценка пригодности, а не заключение
о законности. Для ERROR без досье явно указывается недоступность проверки.
