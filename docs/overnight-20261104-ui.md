# Операторский интерфейс — 04.11.2026

Прочитан продуктовый план. Исследованы код главной, организаций, анализа, готовых КП, HOLD, CRM preview, рассылки и контроля. Основной сценарий сохранён: сбор → анализ → просмотр КП → явная передача в CRM → отдельно разрешённое планирование → проверка ответа/контакт оператором.

Изменения:

- Главная не падает при неизвестном остатке CRM: текст «—» не сравнивается с числом, кнопка передачи остаётся выключена.
- Footer перестал без проверки утверждать «Автоматическая рассылка отключена»; направляет к разделу рассылки.
- HOLD: сортировка, расширенный поиск, предупреждения источника, обезличенные агрегаты.
- Прогноз: переживает отказ CRM, показывает только пригодные будущие слоты; подписи больше не обещают дату завершения всей очереди.
- Контроль: подпись честно сообщает об отсутствии праздничного календаря.

Новые рабочие маршруты, POST-поведение и ширина/layout/увеличенные шрифты не менялись. Макет результатов контакта отдельный HTML, не пункт меню production. Нет массового повторного аудита, новой кнопки рассылки или автоматического follow-up.

Оставшиеся UX-пробелы: технические английские статусы рассылки; локальный отказ followup не равен глобальному запрету рассылки (сейчас предупреждение есть); не все исходы отношений отражены в локальной форме; активная вкладка /mailing и /followup может подсвечивать «Служебное» в базовом respond. Не расширяли число затронутых UI-модулей ради косметики.

Нужна визуальная приёмка человеком после согласованного безопасного старта: широкие таблицы и перенос длинных названий; фильтры и ссылки HOLD; JSON без контактов; пустая/недоступная CRM и выключенная кнопка; карточка followup/сохранение выбранной revision; подписи прогноза. Live браузер и сервер в ревизии не запускались.
