### Безопасность повторов Control Center, 30.10.2026 (текущее правило)

Этот раздел заменяет прежний допуск по общей ошибке `Previous draft failure`.
Первый `Account binding changed` возникал из-за разного сравнения кавычек:
Prepare нормализует имя, Exporter требует точное имя CRM. Перед экспортом
сохранённый Account проверяется по ID, нормализованному имени и домену,
затем используется точное имя CRM. Перепривязки к другому Account нет.

Общая ошибка после повторного HOLD утратила доказательство места остановки.
Пустые steps не доказывают отсутствие CRM-записей. Старый общий HOLD остаётся
заблокированным, включая текущую запись Клиники «А»; повтор Account его не снимает.
Только исходный одиночный `Account binding changed` с прежними дополнительными
проверками допускает исправление эквивалентного написания draft binding.
Первый отказ новых попыток дополнительно сохраняется в `draft_failure`.

Связь Document проверяется полным списком Account: только сохранённый Account;
лишняя связь или неполный ответ дают HOLD до создания Email.

Новые попытки отмечаются `resume_protocol=1` в прежней :draft записи до вызова
Exporter. Повтор проходит все проверки Account/binding/template/PDF и использует
прежние durable steps и точные маркеры. Незавершённая старая попытка без этого
признака требует сверки. Перед POST создания намерение сохраняется атомарно;
потеря ответа/сбой записи ID возможны, поэтому сначала ищется точный маркер.
Нет однозначного результата поиска — HOLD без повторного POST.

В существующем Exporter точечно добавлен durable step `email_attachment`:
намерение до `POST Document/action/getAttachmentList`, ID до PUT Email.
Сохранённое вложение проверяется по sourceId, имени и SHA-256; неизвестный
ответ действия блокирует повтор POST. Успешный PUT с потерянным ответом
восстанавливается чтением Email. Схема API не менялась: getAttachmentList →
attachmentsIds → GET Email и SHA-256. Только Draft, без sendAt и отправки.

Выбранный email новых веб-подтверждений фиксируется в `draft_contact` на этапе
Account; изменение требует HOLD. Без email — DOCUMENT_VERIFIED_NO_DRAFT.
Сохранённые ID при HOLD показаны для сверки, а не как подтверждение успеха.
Операторская процедура: [один контролируемый прогон](crm-controlled-run.md).
Локально: 14 адресных unittest с фейковым API/временным журналом, py_compile
и self-check обработчика UI (Host/Origin/CSRF, stage, READY-выбор/lead ID,
HOLD_IDENTITY, GET без экспорта). Живого API и записи рабочего журнала не было.
Реальная передача Document/Email ещё требует живой проверки оператором.

### Исправление перехода Account → Draft, 30.10.2026

нормализованное совпадение имени (прямые/типографские кавычки), тогда как

## 2. Общая схема работы API

Базовый адрес:

``` text
http://192.168.233.105/api/v1/
```

Заголовки для Python:

``` python
HEADERS = {
    "X-Api-Key": os.environ["ESPO_API_KEY"],
    "Content-Type": "application/json",
}
```

Удобная вспомогательная функция для GET/POST/PUT:

``` python
import os, json, urllib.request

BASE = "http://192.168.233.105/api/v1/"
HEADERS = {
    "X-Api-Key": os.environ["ESPO_API_KEY"],
    "Content-Type": "application/json",
}

def api(method, path, data=None):
    body = json.dumps(data, ensure_ascii=False).encode() if data is not None else None
    req = urllib.request.Request(
        BASE + path, data=body, headers=HEADERS, method=method
    )
    with urllib.request.urlopen(req, timeout=20) as response:
        raw = response.read()
        return json.loads(raw) if raw else {}
```

Примеры путей: - `GET Account/<ID>` --- прочитать карточку
контрагента. - `POST Account` --- создать контрагента. -
`PUT Account/<ID>` --- изменить карточку. - `GET Document/<ID>` ---
прочитать карточку коммерческого предложения. - `POST Email` --- создать
черновик. - `GET Email/<ID>` --- проверить письмо. - `PUT Email/<ID>`
--- обновить письмо, в том числе список `attachmentsIds`.

## 5. Коммерческие предложения: `Document` и PDF-файл

В EspoCRM это две связанные сущности: 1. **Файл PDF** хранится как
вложенный файл; у него есть ID файла. 2. **Запись `Document`** описывает
документ и содержит `fileId` и `fileName`.

Пример чтения записи документа:

``` python
document_id = "ВСТАВЬТЕ_ID_DOCUMENT"
doc = api("GET", "Document/" + document_id)
for field in ("id", "name", "fileId", "fileName", "status", "publishDate"):
    print(field, "=", doc.get(field))
```

### Важное уточнение об исходной загрузке файла

В журнале текущей сессии подтверждены итоговые `Document ID`, `fileId` и
`fileName` для пяти PDF (см. раздел 9). Однако точная исходная команда,
которой файл с локального диска впервые загружался в файловое хранилище
EspoCRM, в доступном журнале не сохранилась. Поэтому здесь она **не
выдумывается**. Для повторной загрузки нового файла нужно использовать
сохранённый рабочий скрипт загрузки из проекта/терминальной истории либо
отдельно зафиксировать его после успешного повторного запуска.

## 6. Создать черновик письма

**Обязательное поле:** `from`. Запрос без него возвращал HTTP 400 с
`validationFailure`, `field: from`, `type: required`. Передача только
`fromAddress` не заменяет поле `from`.

Рабочий шаблон создания черновика:

``` python
account_id = "ВСТАВЬТЕ_ID_КОНТРАГЕНТА"
recipient = "clinic@example.ru"
subject = "Коммерческое предложение LexRadar — Название клиники"

draft = api("POST", "Email", {
    "name": subject,
    "subject": subject,
    "from": "golwebstudio@bk.ru",
    "to": recipient,
    "bodyPlain": (
        "Здравствуйте!\n\n"
        "По результатам предварительного анализа вашего сайта "
        "подготовлено коммерческое предложение.\n\n"
        "Документ прилагается.\n\n"
        "С уважением,\nКоманда LexRadar"
    ),
    "isHtml": False,
    "status": "Draft",
    "parentType": "Account",
    "parentId": account_id
})
print("ID черновика:", draft["id"])
```

Если карточка контрагента не содержит email, не подставляйте выдуманный
адрес. Черновик можно оставить без адресата и дополнить после

## 7. Проверенный способ прикрепить PDF к черновику

**Это ключевой рабочий механизм, проверенный 28.10.2026.**

Не создавайте вручную `POST /Attachment` с полями `parentId` и
`sourceId`: такая попытка возвращала HTTP 400. Рабочая
последовательность:

1.  Вызвать штатное действие `POST /Document/action/getAttachmentList`,
    передав ID записи `Document`, поле `attachments` и
    `parentType: Email`.
2.  В ответе CRM возвращает объект вложения с собственным ID и
    `sourceId` исходного PDF.
3.  Передать ID возвращённого вложения в `attachmentsIds` письма через
    `PUT /Email/<email_id>`.
4.  Повторно прочитать письмо и убедиться, что `attachmentsNames`
    содержит нужное имя PDF.

Пример для уже созданного документа и черновика:

``` python
document_id = "ВСТАВЬТЕ_ID_DOCUMENT"
draft_id = "ВСТАВЬТЕ_ID_EMAIL"

# Получить/подготовить вложение штатным методом EspoCRM.
result = api("POST", "Document/action/getAttachmentList", {
    "id": document_id,
    "field": "attachments",
    "parentType": "Email"
})

if not result:
    raise RuntimeError("EspoCRM не вернула объект вложения")

doc = api("GET", "Document/" + document_id)
file_id = doc.get("fileId")
filename = doc.get("fileName")

attachment = next(
    (item for item in result if item.get("sourceId") == file_id),
    None
)
if not attachment:
    raise RuntimeError("В ответе нет вложения для нужного PDF")

draft = api("GET", "Email/" + draft_id)
attachment_ids = draft.get("attachmentsIds") or []

if attachment["id"] not in attachment_ids:
    api("PUT", "Email/" + draft_id, {
        "attachmentsIds": attachment_ids + [attachment["id"]]
    })

# Контрольная проверка
check = api("GET", "Email/" + draft_id)
print("Статус:", check.get("status"))
print("Получатель:", check.get("to"))
print("Вложения:", check.get("attachmentsNames"))

if filename not in (check.get("attachmentsNames") or {}).values():
    raise RuntimeError("PDF не подтверждён в черновике")
```

Примечание: действие `getAttachmentList` вызывалось **методом POST** с
JSON-телом. Вызов GET возвращал 404. После `PUT Email/<ID>` вложение
действительно появилось в `attachmentsIds` и `attachmentsNames`.

## 8. Проверить все черновики

Следующая команда выводит черновики, попавшие в первые 200 писем,

result = api("GET", "Email?maxSize=200")

print("Найдено черновиков в полученной выборке:", len(drafts))
