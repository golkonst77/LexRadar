# Достоверность текста и полнота чтения (PR #8)

Извлечение, доступность текста, самозаявленное чтение и юридическое исследование —
разные состояния. Ни полное извлечение, ни просмотр скана не подтверждают нарушение.
Production Decision остаётся HOLD / not_confirmed. Отправка недоступна.

## Новые поля

PageObservation и DocumentObservation имеют optional/default `reading: ReadingState`.
DocumentObservation дополнительно содержит `page_texts`, ключ — номер страницы с 1.
Старые schema_version 0.2/0.3/0.4 сохранены; новые поля имеют безопасные defaults.

ReadingState фиксирует:

- `original_saved`, `source_sha256`: наличие сохранённого оригинала и его локальный хеш;
- `extraction_state`: unknown / complete / partial / failed;
- `text_layer_extracted`, `text_truncated`, `original_chars`, `supplied_chars`;
- `page_count`, `page_limit`, `max_page_chars`, `max_total_chars` и `pages`;
- `provenance`: unknown / reproduced / mismatch / failed / missing_original;
- `text_coverage_complete`: весь текст выбранного протокола доступен без усечения;
- `visual_examined=false`, `legal_research_completed=false`, ограничения.

Каждая PageReading содержит номер, исходный и переданный объём текста, text_available,
truncated и extraction_state: unknown / complete / partial / unread / failed / no_text.
`no_text` означает отсутствие результата извлечения, а не доказанное отсутствие
сведений или обязательного документа. `unread` означает, например, страницу за лимитом.
`text_examination` сначала not_examined. После ответа Verifier это только
acknowledged_text или acknowledged_excerpt — самозаявленное исследование предоставленного
текста, без удостоверения семантического понимания. Визуальный осмотр не выполнялся.

Объёмы указаны в символах извлечённого текста, не в токенах или байтах HTTP-пакета.
Исходный объём неизвестен (null), если извлечение страницы не выполнялось/не удалось.
Общий supplied_chars включает межстраничные разделители, original_chars — сумму
полученных исходных текстов страниц. Ограничение размера всего JSON проверяется
отдельно по UTF-8 байтам; слишком большой пакет отклоняется без молчаливой обрезки.

## Проверка происхождения производных данных

load_packet сначала проверяет реальные размеры, SHA-256, обязательные артефакты,
относительные пути и отсутствие симлинков. PDF повторно извлекается в отдельном
ограниченном процессе из одной копии байтов, чей SHA-256 связывается с текстом.
Общий worker ограничивает память, CPU, время, число страниц и объём текста.
Каждая недоступная/усечённая страница сохраняет своё состояние.

Не совпавшие manifest text/page_texts исключаются из передаваемого пакета:
provenance=mismatch, текст не предоставляется. Ошибка воспроизведения даёт failed.
Подмена или отсутствие артефакта отклоняет досье проверкой целостности. Пакет ещё
раз проверяет файлы после извлечения. Это проверка локальных байтов, а не доказательство
происхождения документа от организации и не удостоверение времени публикации.

HTML нового Collector извлекается стандартным локальным HTMLParser: UTF-8,
нормализация пробелов, исключение head/title/script/style/noscript/template.
Текст сверяется с оригинальным HTML. Это **статический текст**, а не точное воспроизведение
DOM innerText, CSS-видимости или живого сайта; неверная UTF-8 кодировка даёт partial.
JavaScript сайта и внешние ресурсы остаются отключены. Сбор форм по DOM сохранён.

## Цитаты и отрицательные утверждения

TextGrounding A/B получил optional `page`. Существенный положительный факт требует
scope=text_excerpt, конкретного evidence ID, совпадения fact с exact_quote и наличия
цитаты в предоставленном тексте. Для PDF обязателен правильный номер страницы.
Не привязанные утверждения получают unverifiable; `fact_supported` пересчитывается.
Это проверяет только наличие фрагмента, а не юридическую интерпретацию.

AIFinding и Candidate получили search_scope и search_limitations. Область поиска —
самозаявленная. Отрицательная гипотеза A/B может оставаться potential, но fact_supported=false
и с явными ограничениями; это не установленный факт отсутствия. Отрицательные/целодокументные
утверждения по неполному PDF — unverifiable; у Verifier — insufficient_evidence.
Даже полный текст документа не подтверждает отсутствие сведений на всём сайте.

Material теперь содержит reading, fully_examined_text_pages и legal_research_completed=false.
examination=text_only требует text_coverage_complete и полного текста всех отмеченных страниц.
Все номера страниц при усечении хотя бы одной дают partial_text.
Completeness сохраняет прежний счётчик acknowledged страниц и отдельно фиксирует
полностью исследованные текстовые страницы, известный знаменатель и
pdf_full_text_review_fraction. pdf_page_denominator_complete=false при неизвестных
числах страниц; доля известных страниц не выдаётся за весь корпус. Юридическая полнота false.

## Безопасная совместимость

При отсутствующем/unknown reading старого досье полнота остаётся unknown, даже если
повторное извлечение доступно. Номера страниц и проверенные фрагменты могут быть получены,
но автоматически complete/text_only не присваивается. Старый DOM-текст HTML при
невозможности воспроизведения сохраняется как недоверенный excerpt с provenance=unknown,
без подтверждения факта. Входные файлы никогда не переписываются.
Пакетный SHA-256 после изменения протокола отличается: прежнее внешнее утверждение
пакета требует нового preflight и рассмотрения. Платных запросов в этом PR нет.

## Локальный просмотр скана

```sh
lexradar inspect-evidence examples/reading-dossier \
  --evidence document-0003 --page 1 --output work/view-template
```

Команда не открывает PDF и не распознаёт изображение. Человек самостоятельно открывает
original_artifact, указанный в inventory.json, в локальном просмотрщике и проверяет
хеш исходного файла. После просмотра он заполняет observations.json: viewed=true,
самозаявленный reviewer_id, viewed_at с часовым поясом, note и конкретные observations.
Заполненный файл передаётся отдельной командой:

```sh
lexradar record-visual-review examples/reading-dossier \
  --submission work/view-template/observations.json --output work/view-record
```

Выход должен быть новым каталогом вне исходного досье. В нём inventory.json,
observations.json и receipt.json: хеши производных файлов, исходного manifest и
переданной записи; исходные байты переданной записи сохраняются отдельно в submission.json.
Неверный PDF SHA-256, номер страницы или будущая дата дают
invalidated; шаблон — pending; привязанная запись — declared_untrusted. Все состояния
остаются untrusted. Журнал не передаётся автоматически A/B/Verifier и не заменяет
машинное поле visual_examined. Нет OCR, изображения не отправляются LLM.

`verify_sidecar(root, output)` проверяет хеши файлов и повторно воспроизводит inventory
из текущего досье. Изменение производных данных или исходного досье отклоняется.
Даже корректная квитанция — локальная целостность, а не подпись, аутентификация или экспертиза.

examples/reading-dossier содержит только сгенерированные фикстуры:

| Evidence | Случай | Извлечение / доступность | Юридическая полнота |
|---|---|---|---|
| document-0001 / full.pdf | Две текстовые страницы | complete; текст полностью доступен, но not_examined | false |
| document-0002 / partial.pdf | Текст обрезан до 10 символов на страницу, одна страница без текста | partial; text_coverage_complete=false; no_text сохраняется | false |
| document-0003 / unread.pdf | Две страницы без извлечённого текста | Извлечение завершено, текстового слоя не получено; обе страницы требуют просмотра | false |

аутентификация проверяющего и доверенное происхождение нормативных текстов остаются вне MVP.
