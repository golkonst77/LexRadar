# Выборочная повторная проверка HOLD — 05.11.2026

В `control_mvp.py` на `/holds` добавлены чекбоксы для категорий
«Техническая недоступность / ограничения сбора» и
«Надёжность доказательств требует проверки», счётчик выбора и кнопка
«Повторно проверить выбранные». В фильтре одной из этих категорий можно
выбрать все показанные строки; поиск ограничивает этот выбор.
Ориентир задания — 18 + 19 организаций; числа не зашиты в код и берутся
из актуального workflow. Рабочая база в ходе разработки не проверялась.

POST `/holds/retry` использует существующие Host/Origin/CSRF-проверки.
Под блокировкой очереди повторно проверяется принадлежность выбранных ID
актуальным HOLD разрешённых категорий. Штатные `Jobs.preview_analysis`
и `submit_analysis` создают обычный пакет `analysis-batch` / `analysis-site`.
Используется существующий режим явно выбранных повторных проверок;
сценарий «только новые сайты» не менялся. Дубли нормализованных доменов
и активные задания исключаются штатной очередью. Оператор видит количество
выбранных, поставленных и пропущенных записей, причины пропуска и ссылку
на прогресс. Повторная отправка не создаёт активных дублей.

Анализатор, `observation()`, правила READY и формирования КП не изменены.
Сохраняется штатный `ignore_robots=False`: повтор не обходит robots.txt.
Постановка не повышает HOLD до READY и не создаёт КП; новый результат
обрабатывается существующим процессом. Исторические строки не переписываются.
CRM, рассылка и шаблоны не менялись; существующие чужие правки сохранены.

Проверено: `python3 -m py_compile control_mvp.py`; один автономный
assert-based self-check `/tmp/hold-retry-selfcheck.py` с SQLite `:memory:`
и без создания worker. Проверены HTML выбора и nonce, повтор ранее успешного
задания с коммерческим HOLD, нормализация www/регистра/http/https,
исключение дублей и активных заданий, отказ для пустого/недопустимого выбора,
сохранение исторической строки. Сетевые запросы и реальные аудиты отсутствовали.
Проверка diff на пробелы выполнена.

Не выполнялись: полный набор тестов, браузерная приёмка, реальные аудиты,
перезапуск сервера. Текущий сервер продолжает работать со своей загруженной
версией кода; применение изменения и живая приёмка остаются оператору.
