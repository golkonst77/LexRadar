## Правила и результаты

Планировщик next_slot:29 — пн–пт 09:00–18:30 МСК (конец окна 19:00 исключён), 20 слотов/день, шаг 30 минут, позже now+10 минут и хвоста назначений. График не менялся. UTC без offset в Espo трактуется как UTC; отображение — Москва. dateSent, а не sendAt, используется для «Отправлено сегодня».

Подтверждённые ошибки старого UI:

- API мог отказать до slots=[], после except происходил UnboundLocalError. Теперь состояние инициализировано заранее и пригодность прогноза сбрасывается при любом отказе сверки.
- Прежняя локальная правка поверх 5782753 считала любой slots запасом, включая дубли, выходные и неподходящее время. Теперь запас допустим только при уникальных будущих слотах в графике; микросекунды также исключены.
- timestamp с отрицательным offset терял исходную зону. Теперь fromisoformat разбирается один раз, наивная дата считается UTC, aware переводится в UTC.
- Будущая dateSent не считается сегодняшней отправкой; вместо достоверного числа — неизвестно.
- «Завершение очереди» переименовано в «Последний подтверждённый будущий слот»: блокированные и неназначенные письма в этот горизонт не входят. Запас подписан как эквивалент дней по 20 слотов, а не календарная длительность/обещание доставки.

WAITING_APPROVAL/HOLD/ERROR и неназначенные записи не скрывают запас, если существуют корректные подтверждённые будущие Draft/sendAt. Просроченные слоты исключены из запаса и видны в причине. Все ожидающие письма при этом не считаются назначенными. Статусная таблица остаётся последним локальным снимком; показатели «сегодня» проверяются GET CRM. Возможное расхождение явно подписано. Фильтр только GET.

Подтверждено чтением кода: html не вызывает cycle/enqueue/select/save. cycle(apply=False) всё равно сохраняет локальный журнал, а CLI запускает его в временной копии; для строгой read-only ревизии даже этот CLI не вызывался. Старый mailer_v2 preview тоже пишет events, поэтому его не запускали.

Изолированные случаи: валидный слот вместе с HOLD; отрицательный offset; выходной; два одинаковых слота; просрочка; Sent на границе московских суток; отказ конструктора API, списка и детального чтения. Файл фикстуры очереди остался побайтно тем же. Сеть запрещена mock-проверкой. Дополнительно py_compile и diff --check.

Не доказана live доступность CRM, время её ScheduledJob, фактическая доставка и отсутствие сторонних назначений между двумя GET. Проверка уникальности относится к слотам доступной очереди; all_rows проверяет страницы, но полные карточки чужих очередей дополнительно не читаются. html пока делает много GET без общего кеша — P2 по росту и таймаутам, не исправляли архитектурно.

Потенциальный P0: внешний писатель меняет Email после последнего GET перед PUT. Локальные lock не являются транзакцией EspoCRM. Факт двойной отправки не установлен. Ночной ремонт worker запрещён. План: изолированный FakeAPI с гонкой, проверка всех писателей и владельцев очередей, согласование серверной/операционной сериализации, отдельный контролируемый тест на собственном адресе только с новым разрешением. Никаких автоматических повторных отправок.
