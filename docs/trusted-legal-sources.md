# Проверяемые нормативные карточки (PR #9)

Это локальная инфраструктура подготовки оснований, а не юридическая экспертиза.
Официальные сайты, реестры и платные API не вызываются. Подлинность публикации,
актуальность редакции и личность проверяющего **не подтверждаются**.
Production Decision остаётся HOLD/not_confirmed; клиентский выпуск и отправка запрещены.

## Раздельные результаты

| Измерение | Что вычисляется | Что не устанавливается |
| --- | --- | --- |
| technical_integrity | Наличие безопасного локального оригинала, точный SHA-256 байтов, вхождение дословной цитаты, внутренние противоречия | Происхождение и истинность текста |
| authenticity | Всегда unverified | Публикация действительно получена с официального ресурса |
| revision_confirmation | Всегда unverified | Редакция подтверждена независимым источником |
| temporal_claim | Условное сопоставление даты события с заявленными периодами | Норма действительно действовала на эту дату |
| legal_force | Всегда unverified | Юридическая обязательность источника |
| applicability | Всегда unestablished | Норма относится к конкретному оператору и деятельности |
| factual_violation | Всегда unestablished | Доказан факт нарушения |

`consistent` означает согласованность локальных данных, а не проверенный закон.
Вручную написанный текст с правильным SHA-256 может быть consistent, но остаётся unverified.
URL pravo.gov.ru, claimed_official, claimed_status=current_confirmed, human_review,
claimed_reviewer и утверждения ИИ ничего не повышают. Поля official, verified,
reviewer и status, отсутствующие в новом контракте, отклоняются strict-схемой.
Старые самозаявленные поля LegalSource сохраняются, но доверия не создают.

## Карточка

Полная машинная схема: [card.schema.json](../examples/legal-sources/card.schema.json).
Модель: `verifier/legal_cards.py::LegalSourceCard`.

| Поля | Значение |
| --- | --- |
| schema_version, id, act_id | Версия карточки, уникальная редакция/положение, заявленный идентификатор документа для группировки редакций |
| source_kind | normative_act / official_explanation / judicial_act / secondary_material / ai_claim |
| domain | Отдельное юридическое направление; не подтверждение применимости |
| act_name, act_number, document_date | Наименование, номер, дата документа; неизвестная дата — null |
| provision, norm_text | Точная структурная единица и дословный фрагмент, проверяемый без нормализации пробелов |
| source_url, publication_id, publication_date | Заявленный локатор и дата публикации; требуется хотя бы URL или идентификатор |
| revision, effective_from, effective_until | Заявленная редакция и период действия; неизвестные даты — null |
| transition_from, transition_until, transition_note | Отдельные условия/даты применения переходного положения |
| checked_at, verification_method | Заявленные дата и способ проверки; не доказательство её проведения |
| text_sha256, original_path | Хеш точных байтов сохранённого UTF-8 текста и относительный путь внутри каталога реестра |
| revision_check_basis | Заявленный источник подтверждения редакции; требуется независимая перепроверка |
| claimed_lifecycle, source_availability | Заявления об отмене/действии и доступности; не результат сетевой проверки |
| intended_use | binding_norm или context; не-НПА нельзя автоматически использовать как обязательную норму |
| limitations, uncertainties | Явно перечисленные ограничения и неопределённости |
| claimed_official, claimed_status, claimed_reviewer | Самозаявленные сведения, не создающие доверия |

Обязательные ключи дат могут иметь null: система не заполняет неизвестное догадками.
source_kind и act_id также самозаявленные: нельзя обнаружить все случаи статьи,
замаскированной под закон, только по её JSON-категории. Поэтому даже normative_act
с технически корректной карточкой не получает юридического подтверждения.

## Локальный workflow

1. Человек сохраняет текст/фрагмент и происхождение доступными ему законными средствами.
   LexRadar не скачивает его и не обходит ограничения среды.
2. Заполняет metadata, включая точную цитату и неопределённости.
3. `prepare` копирует неизменённые UTF-8 байты, вычисляет их хеш и создаёт отдельный
   каталог: original.txt, card.json, registry.json, report.json и неподписанный review.json.
4. `check` заново читает оригиналы и проверяет карточки для указанной даты события.
5. Независимый проверяющий может заполнить review.json и сохранить декларацию через
   `review`. Запись связывается с canonical SHA-256 карточки (включая цитату, URL,
   редакцию и даты), SHA-256 оригинала и датой события; изменение связанного содержания
   или утрата целостности оригинала даёт invalidated.
6. Даже совпадающая запись получает только untrusted. Аутентификации проверяющего,
   электронной подписи и удостоверения происхождения нет.

```bash
lexradar legal-source prepare \
  --metadata examples/legal-sources/metadata-v1.json \
  --text examples/legal-sources/originals/v1.txt \
  --event-date 2025-06-01 --output work/source-v1
lexradar legal-source check \
  --registry examples/legal-sources/registry.json \
  --event-date 2026-06-01 --output work/source-check
# После самостоятельного заполнения неподписанной декларации:
lexradar legal-source review \
  --registry work/source-v1/registry.json --source-id synthetic-v1 \
  --submission work/source-v1/review.json \
  --event-date 2025-06-01 --output work/source-review
```

Последняя команда отклонит незаполненный шаблон. Новые выходные каталоги не должны
существовать; существующие источники не изменяются. `review` не дописывает доверенный
статус в карточку. Отчёт хранит SHA-256 исходной декларации и её статус, а не сертификат.
Пробелы/форматирование JSON не входят в canonical binding, все семантические поля входят.
SHA-256 доказывает связь локальных данных, а не происхождение или юридическую силу.

## Редакции и ограничения применения

Границы declared-интервалов включительны. Для двух соседних редакций последний день
старой и первый день новой должны различаться. Нет выбора по дате загрузки,
номеру версии или «самой последней» записи.

В [registry.json](../examples/legal-sources/registry.json) два **синтетических** положения
одного тестового акта: v1 — 01.02.2024–31.12.2025, v2 — с 01.01.2026.
Для события 01.06.2025 первая редакция within_declared_interval, вторая not_yet_effective.
Для 01.06.2026 первая expired, вторая within_declared_interval. Обе unverified.
Дословные тексты явно помечены NOT AN OFFICIAL SOURCE / NOT Russian legislation;
это не придуманный официальный закон и не материалы реального аудита.
Третья запись — синтетическая вторичная статья, не НПА, с неизвестным периодом.

Проверяются перекрытия редакций одного act_id/provision, в том числе вне даты события,
неизвестные начала периодов, противоречивые даты и идентификационные метаданные.
Переходные сроки условно пересекаются с основным периодом, но их юридическое толкование
остаётся неизвестным. Утраченная редакция может быть заявленно релевантна прошлому
событию; заявление об отмене без даты даёт ambiguous. Ни expired, ни declared repeal
не становятся самостоятельно юридически подтверждённым опровержением.

## Интеграция и безопасность

SourceRegistry 0.4 получил необязательный cards; legacy sources и attest-source сохранены.
Старые записи остаются unverified. Новые карточки и старые записи не могут иметь
одинаковые id. `load_registry` закрепляет локальный каталог приватным, не импортируемым
из JSON полем. `assess_registry` воспроизводит проверки оригиналов при каждом вызове.
Отсутствие локального корня означает unavailable integrity, а не доверие.
Verifier получает card_assessment и конкретные reasons в обоих этапах; Stage I не получает A/B.
Production Decision использует тот же загрузчик, но по-прежнему не имеет ветки GO.

Локальные входы ограничены 6 MB, оригиналы — только UTF-8 текст. Symlink, абсолютные
пути, выход через `..`, отсутствующие и повреждённые файлы не подтверждают целостность.
PDF/HTML-оригиналы нормативных публикаций, OCR, проверка цифровых подписей, анализ
полного корпуса поправок и официальные источники онлайн в этом PR не реализованы.
Исходный PDF можно сохранить отдельно, но его происхождение не удостоверяется этим workflow.
Недоступность официального ресурса фиксируется заявлением unavailable и всегда unverified.
Разъяснения ведомств вне прежнего publication-allowlist также не получают подтверждения.

Будущее доверенное подтверждение потребует отдельно спроектированного механизма
удостоверения происхождения, независимой аутентифицированной проверки редакции,
юридической силы и применимости к оператору/деятельности/периоду. Это новые основания,
а не флаг trusted в JSON. До их реализации результат не повышается автоматически.
