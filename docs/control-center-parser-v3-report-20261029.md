## Реализовано

- Форма «Собрать организации»: реальные восемь отраслей, N=1–1000 пригодных
  лидов, необязательное название. Источник выбирает Parser, вся Россия.
- Предпросмотр реальных аргументов и уникального каталога, ограничений и
  фактической пригодности. Второе явное подтверждение с CSRF и одноразовым
  токеном, срок 15 минут; GET не начинает сбор.
- Существующая SQLite очередь: один исполняющий поток, новые params/result,
  таймаут Parser 4 часа, локальных проверок 60 секунд. Параметры CLI фиксированы,
  shell не используется. Только новые UUID-каталоги в `.control-center-state`.
- Статусы, время UTC, ограниченный stdout/stderr, причина ошибки, сводка,
  число пригодных, автообновление активной карточки каждые 5 секунд.
- Отмена группы собственных процессов; supervisor прекращает сбор при
  исчезновении владельца. После перезапуска нет автоматического продолжения.
- Успех проверяется по exit code, сводке и реальному CSV. Недобор N при exit
  code 0 и повреждённая сводка дают failed. Импортируются только успехи.
- Лиды с привязкой к запуску, фильтр запуска, скачивание CSV с защитой формул
  и безопасным открытием. Исторический импорт сохранён, упоминания раздельно.
- Читаемая широкая таблица, карточка с запуском/контактами/источником,
  действия на главной и последние ошибки. Названия отчётов человеческие,
  путь вторичен; сохранённый PDF больше не объявляется утверждённым КП.
- Диагностика исходников, Python, версии Playwright, наличия Chromium,
  DISPLAY для Orgpage и записи состояния. Нет отображения окружения/секретов.

RUN заменяется UUID панели. Процесс запускается через локальный
`control_parser_runner.py`, наблюдающий за родителем. Старое main.py не используется.
Python автоматически берётся из существующей `.venv`, иначе из панели.
Браузеры читаются из cache владельца; HOME/TMPDIR запуска направлены в RUN.
Новая база исключает смешивание накопительных экспортов; resume не используется.

но итоговый CSV уже имеет «Организация/Официальный сайт/Исходная карточка»:
существующий импорт совместим, отдельное преобразование не добавлялось.

N означает пригодные уникальные сайты. Помимо контакта Parser проверяет
доступность и исключает явный mismatch, но допускает unknown/probable бренда
и подтверждённую защитную страницу. Это не строгое доказательство официальной
юридической принадлежности; отличие показано перед запуском. Рейтинг —
описательный. Строительство требует совпадающий конечный домен и тематику.
CLI может завершиться с кодом 0 при safety_page_limit и недоборе N — панель
такой результат успешным не считает.

## Что не реализовано и ограничения

- Реальный браузер и сеть не проверены по прямому запрету задания. Локальная
  готовность не доказывает наличие всех библиотек Chromium, доступ источника
  или отсутствие CAPTCHA. Установок зависимостей не было.
- Orgpage требует оконный Chromium в исходном коде. Без доступного DISPLAY
  серверу сбор честно недоступен; парсер для обхода не изменён.
- Отдельный скрининг выбранных лидов не подключён. Найден `lexradar batch-screen
  <urls> --output <directory>` в основном проекте: бесплатный ограниченный
  проход с собственными сессиями worker-процессов. Для него нужна отдельная
  интеграция контроля потомков, иначе отмена только группы Parser недостаточна.
  Встроенный quick_screen Parser уже выполняется при сборе.
- Нет новых аудитов, генерации PDF, платных API, CRM-записи, писем и рассылок.
  Схемы и журналы EspoCRM не менялись. Существующие связи материалов остаются
  только по однозначному домену, без заявления о подтверждённом юрлице.
- Сохранённые PDF и анализы различаются; одобрение КП по имени PDF не выводится.
  Отдельный каталог юридически утверждённых КП не выдуман.
- Частичные/отменённые файлы сохраняются в RUN, но не публикуются как успех.
  SIGKILL не гарантирует финального CSV. Возобновления из UI нет.
- Индекс новых запусков: 64 успешных запуска / 32 МБ CSV / 20 000 лидов,
  с предупреждением при превышении. CSV выдаётся до 8 МБ.
- Панель локальная, без пользовательской авторизации, не для публикации наружу.
