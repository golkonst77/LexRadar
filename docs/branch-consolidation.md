## Разрешение пересечений с PR #20

- `runner.py` использует общую очередь и журнал pdf_priority из #20. В общий
  словарь перенесены признаки ПДн/сторонних операторов из #19; внутри прямых
  признаков политики идут перед согласиями, затем остальные раскрытия. Контекст
  страницы и устойчивый порядок URL сохранены. Дублирующей очереди нет.
- `reading.py` объединяет инертный SVG из #19 с unread_page_ranges из #20;
  неоднозначные HTML script/template по-прежнему не допускаются к полному чтению.
- `cli.py` сохраняет все PDF page/text limits #20 и file/total-byte limits #19,
  добавленные ранее команды batch-screen и ocr-document.
- Budget allocator Primary, полные цитаты/соседние реквизиты, Windows PDF Job Object,
  воспроизводимость PDF, fail-closed packet bounds и эталонные экспорты #20
  сохраняются без отката.
- Linux-only batch/OCR ресурсы импортируются при исполнении, чтобы общий код
  и скрининг работали на Windows. Исполнение batch/OCR вне Linux явно отклоняется;
  поддержка нового runtime не добавлена.

CI выполняет полный набор на Linux с Chromium/Poppler/Tesseract rus+eng и все
применимые тесты на Windows с Chromium. Linux-only supervision/OCR tests на
Windows явно пропускаются. Ruff, существующие CLI и benchmark сохранены; CLI help
дополнительно проверяет совместное присутствие параметров. Интеграционная
регрессия проверяет SVG-суффикс, порядок PDF, журнал пропусков и reading_gaps.

## Сохранившиеся ограничения

Это внутренний технический скрининг, HOLD/not_confirmed; клиентская отправка
запрещена. Реальный аудит/контрольный прогон scz.ru и сравнение «до/после» не
проводились и не объявляются пройденными. Исторические числа из описания #19
не являются приёмкой этой интеграции. Приоритет PDF эвристический, покрытие
ограничено бюджетом, OCR не импортируется автоматически в Primary/Verifier/ranking
и не устанавливает visual/legal review. Batch/OCR требуют Linux и отдельного
разрешённого окружения; live-сайты, формы и платные LLM не запускаются.
