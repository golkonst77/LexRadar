## Реализовано

### A. Организации

- Существующие CSV с `;`/UTF-8 BOM и crm-candidates.json сохранены.
- Лиды и упоминания остаются разными разделами. Исправлено прежнее неверное
  предположение: даже единственная организация в audit.json не получает сайт
  проверяемого ресурса автоматически.
- Поиск по названию/сайту/ИНН/контактам, фильтр статуса, сортировка А–Я/Я–А/источник,
  пагинация по 20, карточки с исходной строкой, контактами и происхождением.
- HTTP(S)-сайты кликабельны, HTML экранируется. Пустые контакты остаются пустыми.
- Дата файла импорта обозначена как mtime, без выдуманной даты реального импорта.

### B. Анализы и PDF

- Связь материалов сайта с единственным лидом по нормализованному домену.
  Отдельные поддомены не объединяются; несколько лидов на домене блокируют связь.
  Цитаты и случайные совпадения имён не используются.
- Связанный PDF берётся только рядом с сопоставленным audit.json. Это связь
  материалов сайта, не подтверждение юрлица или адресата КП.
- Показываются фактические стадии, source_started_at/assessed_at, ограничения,
  наблюдения, гипотезы, статусы проверки и сохранённые цитаты. Юридические
  нарушения не объявляются установленными.
- Отдельный индекс сохранённых аудитов и разрешённых PDF, исходный JSON,
  просмотр/скачивание PDF. Нет генерации и изменения утверждённых шаблонов.
- Ограниченный общий индекс, кэш содержимого по списку файлов/размеру/mtime,
  проверка изменений не чаще раза в 5 секунд; ручное перечитывание POST.
- PDF проверяется по пяти байтам при индексации и читается полностью только
  при выдаче. Лимит 50 МБ, обычные файлы, nofollow для каждого компонента пути.

### C. Локальные задания

- Рабочая постоянная SQLite-очередь, один активный дочерний процесс, flock
  против второго экземпляра исполнителя. Состояние только в копии проекта.
- queued/running/succeeded/failed/cancelled, начало/окончание UTC, причины,
  stdout/stderr до 64 КиБ, безопасный Unicode, таймаут 60 секунд.
- Два фиксированных типа: inspect-import и offline-results. Это проверки
  сохранённых файлов, не производственные CLI и не сетевой сбор.
- Предпросмотр точной команды и отдельное подтверждение постановки.
- Отмена queued и running; завершается только собственный дочерний процесс.
- При перезапуске running → failed, queued → cancelled; автоматического
  восстановления запуска нет. При Ctrl+C задания отменяются.
- Дочернему процессу не передаются API-ключи и остальные переменные окружения.
- CSRF-токен процесса, обязательное подтверждение, Host/Origin-проверки,
  ограничение формы и запрет chunked. GET не запускает действий на диске.

### D/E. Разделы и интерфейс

- `/reports`: организация/домен/путь, тип, диапазон дат, пагинация, детали.
- `/crm`: локальный read-only preview *crm-result.json фактической формы
  CRM_PREPARE_ONLY; сохранённые ID не объявляются проверенными в живой CRM.
  Произвольные поля/секреты не рендерятся. Нет кнопок записи или отправки.
- `/settings`: пути источников и состояния, доступность, индекс, предупреждения,
  ручное перечитывание. Переменные окружения и ключи не показываются.
- Главная: реальные счётчики доступного индекса, последние задания и материалы.
- Единая русская навигация, тёмная тема, прокрутка таблиц, мобильные отступы,
  пустые состояния, ошибки и предупреждения. Убраны декоративные «Скоро».

## Допущения и сознательные ограничения

1. Без ответов пользователя безопасный запуск трактуется как офлайн-проверка
   существующих файлов. Боевой Parser v3, аудит, генерация PDF, CRM-экспорт,
   почта и массовые внешние задания не включены. Команда боевого парсинга
   не выдумана: её интерфейс здесь не подтверждён.
2. В интерфейсе зафиксированы MedAdvisor для медицинских организаций,
   Orgpage для остальных, вся Россия и N пригодных контактов; полноценной
   формы параметров сетевого запуска и production command preview пока нет.
3. Дата импорта неизвестна при отсутствии явной метки; показывается честная
   дата файла. Статус отсутствующего анализа не придумывается.
4. Разрешены только известные имена PDF. Произвольные PDF/HTML/секреты/.env
   не публикуются; другие форматы отчётов пока не индексируются.
5. Возможна задержка обновления до 5 секунд. Замена содержимого с сохранением
   размера/mtime требует ручного refresh. Лимиты и неполнота показаны в UI
   и подробно перечислены в docs/control-center.md.
6. PDF signature не заменяет проверку содержимого или юридическое одобрение.
7. Панель локальная, без пользовательских учётных записей; не публиковать её
   наружу. Токен не защищает от недоверенного приложения того же пользователя.
8. Журнал не удаляется автоматически: 100 queued/running, 1000 заданий всего.
   CRM preview показывает первые 200 строк. Настройки путей только через CLI.
9. Статусы/ID CRM — сохранённые факты файла, без живой верификации, без доступа
   к постоянным домашним журналам. «Не отправлено панелью» не означает, что
   внешние процессы никогда не отправляли письмо.
10. Аварийное падение Python без graceful shutdown не имеет внешнего watchdog;
    разрешённые дочерние проверки сами конечны и не выполняют сетевых операций.

## Запуск после возвращения

Пользователь останавливает прежний сервер Ctrl+C и запускает:

```bash
cd /home/golkonst/src/LexRadar-web-control
python3 control_center.py --parser-dir /home/golkonst/lexradar-data --results-dir /home/golkonst/src/LexRadar-compact --port 8080
```

Практический следующий шаг: открыть `/organizations`, `/reports`, `/settings`,
выбрать конкретный реальный запуск при предупреждениях, затем в `/jobs`
предпросмотреть и запустить «Проверить существующий импорт». Проверить UI
в браузере. После этого отдельно согласовывать и проверять CLI реального
Parser v3/аудита с явными лимитами, без включения почты и CRM-записи по умолчанию.
