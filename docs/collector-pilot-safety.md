# Collector: robots.txt, последовательная нагрузка и пределы пилота

Публичный сбор использует одну `CrawlSession` поверх существующего транспорта с DNS pinning,
проверкой каждого редиректа, SSRF-ограничениями, TLS и лимитами файлов. Нет параллельных HTTP-запросов,
отправки форм, авторизации, исполнения JavaScript, смены User-Agent или обращения к LLM.
Новые настройки находятся в `CrawlOptions`, отдельно от `Limits` и формата досье v0.2.
Это сохраняет формат старых CollectionResult и хеширование пакетов v0.3–v0.5.

## robots.txt

Первым запрашивается `/robots.txt` того же origin (схема, hostname, порт) с неизменным заголовком
`LexRadar/0.2 (bounded evidence collector)` и product token `LexRadar`.
Проверка выполняется перед каждым HTTP-запросом HTML/PDF и **перед отправкой каждого следующего
шага редиректа**. Разрешение исходного URL не является разрешением его конечной цели.

Выбирается самая специфичная совпадающая группа User-Agent без учёта регистра, включая
versioned LexRadar; несколько одинаково специфичных групп объединяются. Если специфичной
группы нет, применяются группы `*`. Правила путей учитывают регистр, query, UTF-8/percent-encoded
октеты, `*`, конечный `$`, наиболее длинное совпадение; при равной длине Allow имеет приоритет.
Пустой Disallow не запрещает обход. Дробный Crawl-delay поддерживается; берётся максимальное
значение из выбранных групп. Sitemap и другие расширения не запускают дополнительные запросы.

**Консервативная политика отсутствия разрешения:** обход блокируется на весь запуск, без
повторной попытки, если robots.txt не получен, вернул любой статус кроме 200 (включая 404,
403, 429 и 5xx), перенаправляет, превышает предел размера, имеет неверный MIME, некорректный
UTF-8, неоднозначный синтаксис или некорректный Crawl-delay. В частности, 404 не превращается
в разрешение. Это намеренно строже обычных трактовок отсутствующего robots.txt.
Редиректы **самого robots.txt не следуются**, даже в пределах origin: неизвестная политика
не даёт разрешения запрашивать произвольную цель bootstrap-редиректа.

Принимается только `200 text/plain`, максимум min(500000 байт, текущий предел файла).
Пустой успешно полученный файл или файл только с комментариями не содержит запретов.
Корректные группы только для других агентов не ограничивают LexRadar. Ответ без распознаваемых
групп с непустыми директивами (например, Sitemap-only) блокируется как неоднозначный.
Публичные страницы robots.txt не является разрешением обходить CAPTCHA, авторизацию
или получать непубличные сведения.

Чтобы не использовать неоднозначную нормализацию путей как обход robots, дополнительно
блокируются dot-сегменты, encoded slash/backslash и encoded percent в **path**. Это может
исключать некоторые легитимные URL. Query проверяется по обычным robots-правилам.

## Частота и бюджеты

По умолчанию минимальный интервал между началами попыток запросов — **2 секунды**.
Фактический интервал: `max(min_delay_seconds, Crawl-delay)`. Он применяется также после
robots.txt и к каждому шагу HTTP-редиректа. Запросы последовательные; robots.txt кэшируется
только внутри одного запуска. Автоматических повторов сетевых запросов нет.

- `max_requests=64`: предел попыток, включая robots.txt, редиректы и попытки, которые позже
  остановились на DNS/egress. Отдельно считается подтверждённая отправка HTTP-запроса.
- `max_duration_seconds=300`: бюджет монотонного времени всей сессии, включая запуск браузера,
  обработку материалов и ожидание. Если для обязательного ожидания не хватает оставшегося
  бюджета, следующий запрос не начинается.
- HTTP I/O timeout ограничивается остатком общего бюджета; обязательная задержка не
  расходует отдельный HTTP timeout. Существующий общий timeout цепочки редиректов сохранён.
- Рендеринг и PDF-извлечение получают ограничение по остатку времени. Это кооперативный
  deadline, не жёсткое убийство процесса: завершение браузера и запись файлов могут завершиться
  немного позже; произвольный зависший внешний процесс этой сессией не удостоверяется.
- После транспортной ошибки/таймаута/DNS-сбоя при сборе контента следующие запросы останавливаются.
  HTTP-ошибка страницы, запрет robots или отклонённый небезопасный редирект остаются отдельным
  зафиксированным отказом; остальные допустимые цели могут проверяться.

Минимальная настраиваемая задержка — 0.1 с, максимум — 60 с; для публичного пилота оставляйте
2 с или увеличивайте. Максимальные допустимые пределы: 1000 попыток и 3600 с. Лимиты HTML/PDF,
байтов и редиректов работают дополнительно; бюджет не гарантирует получение всех 10+10 материалов.
Один запуск не создаёт параллельной нагрузки. Координация нескольких отдельных процессов
не реализована: оператор должен запускать один Collector на один сайт.

## Журнал и артефакты

Новый выходной каталог содержит обычные `collection.json` и `artifacts/`, а также:

- `crawl/requests.jsonl`: время с часовым поясом, robots_received / robots_unavailable,
  разрешённые/запрещённые URL, редиректы, установленный интервал и реальное ожидание,
  попытки/подтверждённые отправки, HTTP-статусы, ошибки, причина остановки;
- `crawl/summary.json`: options, User-Agent, статус robots, причина остановки, число попыток
  и отправок, число запрещённых целей и длительность;
- `crawl/robots-response.txt`: реально полученные байты ответа 200, SHA-256 которого фиксируется
  для корректного robots.txt. Даже ошибочный 200 может быть сохранён, но не даёт разрешения.

Эти sidecar-файлы описывают политику обхода и **не** считаются самостоятельными юридическими
доказательствами. Они не добавляются в старый JSON-пакет аудиторов. Отказ robots обозначает
невозможность проверки по политике, а не HTTP-недоступность страницы или отсутствие документа.
При частичном сбое HTML/текст/PDF сохраняются по прежним правилам `partial`; новые лимиты не
удаляют уже полученные артефакты. При ошибке запуска браузера журнал сохраняет collector_error,
но успешный manifest не имитируется.

Основные причины остановки: robots_unavailable, request_count_limit, crawl_duration_limit,
network_error, download_byte_limit, collector_error, page_limit, document_limit, queue_exhausted и
queue_exhausted_with_denials. Завершение очереди не удостоверяет полноту сайта.

## Запуск в разрешённой сетевой среде

```bash
lexradar collect https://example.org/ --output work/public-pilot \
  --max-pages 10 --max-documents 10 --timeout 10 \
  --min-delay 2 --max-requests 64 --max-duration 300
```

Каталог должен быть новым. Здесь пример, а не выполненный публичный обход. Программный API:

```python
from pathlib import Path
from lexradar.collector import CrawlOptions, Limits, collect

result = collect(
    "https://example.org/",
    Path("work/public-pilot"),
    Limits(max_pages=10, max_documents=10),
    crawl_options=CrawlOptions(min_delay_seconds=2, max_requests=64, max_duration_seconds=300),
)
```

Controlled pilot v0.5 также использует эту политику по умолчанию и сохраняет своё отдельное
подтверждение SHA-256 конфигурации. Для настройки дополнительных crawl-options используйте
Collector CLI/API; параметры и журнал явно сохраняются отдельно, без изменения прежнего
формата утверждённой pilot-конфигурации.

Среда должна разрешать домен, DNS и используемый транспорт. **Текущий pinned транспорт не
поддерживает обязательный HTTP-прокси**, останавливается при его наличии и не удаляет proxy
переменные. Один allowlist домена не решает эту несовместимость. Нужна среда, где прямой
DNS-pinned HTTPS-egress разрешён её политикой, либо отдельная реализация совместимого
контролируемого транспорта в будущей задаче. Не отключайте прокси или SSRF-проверки для обхода
политики Codex. Между origin редиректы запрещены, в том числе на другой hostname/схему/порт.

## Проверки

Все HTTP-тесты — loopback-фикстуры с test-only exact host/port policy; публичные сайты не
используются. В pytest виртуализируется только pacing-clock, а реальные DNS/socket/browser
таймауты сохраняются. Отдельный loopback-тест проверяет реальную минимальную задержку и
общий deadline во время HTTP-запроса. CI также выполняет бесплатный синтетический benchmark
v0.5 с настоящими стандартными задержками.

Юридическая логика, Gateway, A/B, Verifier, их независимость, запрет автоматического GO и
отправки сообщений не изменены. Реальный обход doktstom.ru и платные LLM-запросы не выполнялись.
