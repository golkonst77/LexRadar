# LexRadar Control Center

Локальная панель на стандартной библиотеке Python 3, Linux/POSIX.
Источники открываются только на чтение. Очередь выполняет локальные проверки
и отдельно подтверждённый запуск реального Parser v3. Для просмотра пакеты
не нужны; для сбора используются уже установленные зависимости Parser v3.

## Запуск и перезапуск

```bash
cd /home/golkonst/src/LexRadar-web-control
python3 control_center.py --parser-dir /home/golkonst/lexradar-data --results-dir /home/golkonst/src/LexRadar-compact --port 8080
```

Откройте http://127.0.0.1:8080/. Bind всегда `127.0.0.1`.
Для перезапуска пользователь останавливает свой прежний процесс через Ctrl+C
и повторяет команду. Панель сама не перезапускает сервер и не занимает чужой порт.
Одновременно допустим только один исполнитель на каталог состояния.

`--results-dir` — **источник существующих результатов**, а не рабочий каталог
заданий. Можно указать основной проект или конкретный каталог одного запуска,
чтобы уменьшить объём индекса и увидеть результаты за пределами лимита обхода.
По умолчанию — текущий каталог. Источник не изменяется.
`--parser-dir` — каталог готовых экспортов Parser v3, по умолчанию
`/home/golkonst/lexradar-data`. Для отдельного исходного экспорта допустим
`/home/golkonst/parser-smoke-20261029`.

Новые задания, SQLite и журналы находятся только в
`/home/golkonst/src/LexRadar-web-control/.control-center-state/`.
Каталог игнорируется Git, права каталога 0700, базы и lock-файла 0600.
Нельзя указывать путь служебного состояния через HTTP.

## Маршруты

| Маршрут | Назначение |
|---|---|
| `/` | Фактические счётчики доступного индекса, последние задания и материалы |
| `/organizations` | Лиды Parser v3, поиск, статус, сортировка, страницы по 20 |
| `/organizations/<id>` | Реальные контакты, источник, исходная строка, связанные материалы сайта |
| `/mentions` и `/mentions/<id>` | Отдельные упоминания из аудитов, наблюдения и доказательства |
| `/reports` | Аудиты и готовые PDF, фильтр по домену/имени связанного лида/пути, типу, датам |
| `/reports/<id>` | Стадии, даты, ограничения, наблюдения, гипотезы и ссылки на материалы |
| `/files/<id>` | Разрешённый PDF или исходный JSON аудита; `?download=1` — скачивание |
| `/documents/<mention-id>/<document-id>` | Сохранённый совместимый маршрут PDF из карточки упоминания |
| `/jobs` и `/jobs/<id>` | Сбор организаций, локальные проверки, очередь, журнал, отмена |
| `/exports/<job-id>` | Безопасная копия CSV успешного запуска |
| `/crm` | Исключительно локальный preview сохранённых результатов подготовки |
| `/settings` | Пути, доступность, индекс и диагностика без переменных окружения |
| `/health`, `/api/status` | Доступность процесса; `read_only` относится к источникам |

Неизвестный ID/маршрут или недоступный документ возвращают 404.
Даты файлов в UI — mtime в UTC; это не доказательство даты импорта или одобрения.
У аудита отдельно выводятся сохранённые `source_started_at` и `assessed_at`.

## Источники и привязка

Поддерживаются существующие форматы Parser v3, UTF-8 с BOM или без него:

- CSV, разделитель `;`, обязательные заголовки: `Организация`,
  `Официальный сайт`, `Телефон`, `Email`, `Исходная карточка`.
  ИНН, статус скрининга и прочие исходные поля сохраняются при наличии.
- `crm-candidates.json`: массив объектов с `company_name`, `website`, `phone`,
  `email`, `source_card`; необязательные `inn`, `crm_status`.

Соседний `parser.csv` имеет приоритет над производным JSON, включая случай
повреждённого CSV: потенциально устаревший JSON не используется как подмена.
`lexradar.csv` и `results.csv` не являются экспортами лидов и пропускаются.
ID карточки зависит от пути и содержимого строки, перестановка строк безопасна.
Разные экспорты не объединяются. Отсутствующие контакты не выдумываются.
Наличие официального сайта и телефона либо email отдельно подсчитывается
офлайн-проверкой как минимальная контактная пригодность, без скоринга.

Поиск `q` — подстрока названия, сайта, ИНН, телефона, email без учёта регистра.
`run` — ID успешного запуска панели; `status` — точное сохранённое значение. `sort=name|name-desc|source`.
Фильтры и сортировка сохраняются при переходе по страницам.

Аудиты: `audit.json`, `schema_version=primary-audit-0.1`; упоминания также
читаются из `organizations.json`, `audience=internal_only`, `rows`.
При соседстве для упоминаний выбирается audit.json.
**Даже единственное упоминание не доказывает принадлежность сайта организации.**
Ни target_url, ни URL цитат не подставляются в сайт упоминания.

В карточке лида материалы сайта связываются по нормализованному домену
официального сайта и `audit.target_url`: http/https, www, регистр и завершающая
точка не мешают; поддомены сохраняются раздельно. Несколько лидов на одном
домене означают неоднозначность — автоматической связи нет. Имя организации
и текст цитаты не участвуют в связывании. PDF связан только с каталогом
сопоставленного audit.json. Это связь **материалов сайта**, не подтверждение
юридического лица, адресата КП или разрешения отправки.

Разрешённые PDF: `proposal.pdf`, `proposal-*.pdf`; прочие собранные на сайте
PDF не публикуются через панель. Отдельный PDF без соседнего аудита виден
в отчётах без догадки об организации. Максимум 50 МБ, обычный файл,
проверка `%PDF-`. При индексировании читаются только пять байтов заголовка;
полный файл — при открытии. Содержимое PDF не проверяется на безопасность
или соответствие утверждённому шаблону. Новые PDF не генерируются.

`/reports?q=clinic&kind=pdf&since=2026-10-01&until=2026-10-31&page=2`.
Даты фильтруются по mtime, некорректные даты игнорируются.

## Очередь и POST

В `/jobs` выберите задачу → подтвердите предпросмотр → проверьте команду →
отдельно подтвердите постановку. Доступны только:

- `inspect-import`: чтение экспорта, число лидов/контактно пригодных записей,
  предупреждения формата или лимитов;
- `offline-results`: ограниченный индекс, число аудитов/PDF и предупреждения.

Эти две задачи остаются офлайн-проверками, таймаут 60 секунд.
Предупреждения дают код 1 и `failed` с журналом.

### Реальный Parser v3

Обнаружен `/home/golkonst/src/Parser-v3`, ревизия `5d167de`.
Вход `parser_run.py` подтверждён чтением кода, RUNBOOK и безопасным `--help`.
`main.py` не используется: у него общая БД и миграция при старте.
Каталог исходников фиксирован в `control_parser.SOURCE`, HTTP не принимает
пути, интерпретатор, произвольную команду, регион или агрегатор.
Python: `.venv/bin/python` внутри Parser v3, если он существует; иначе Python
панели. Browser cache: `~/.cache/ms-playwright` владельца панели, только чтение.
Зависимости не устанавливаются автоматически.

Сценарий `/jobs`:

1. «Собрать организации»: выбрать одну из восьми реальных отраслей, N=1–1000,
   необязательное название до 100 символов. Свободная новая тема не поддерживается:
   CLI принимает только восемь отраслей.
2. Подтвердить предпросмотр. Здесь нет сетевого сбора и каталога на диске.
   Показаны точные аргументы, источник, N, уникальный каталог и ограничения.
3. Отдельно подтвердить сетевой сбор. Сервер принимает только одноразовый
   токен предпросмотра, действующий 15 минут. Подмена N при подтверждении
   не меняет сохранённые параметры; повторный POST не создаёт дубликат.
4. Карточка задания обновляется каждые 5 секунд через HTTP Refresh.
   Видны queued/running/succeeded/failed/cancelled, время UTC, параметры,
   stdout/stderr, результат и ошибка. Процент не выдумывается: прогресс — журнал.
5. После успеха — «Лиды этого запуска», фильтр `?run=<job-id>` и CSV.
   Карточка лида содержит название запуска, сайт, контакты, ИНН при наличии,
   исходную карточку, сохранённые поля и доступные материалы сайта.

Фактическая внутренняя команда (RUN — UUID, не ввод пользователя):

```text
/home/golkonst/src/Parser-v3/.venv/bin/python -B -u /home/golkonst/src/Parser-v3/parser_run.py --industry 1 --target 10 --max-cards 200 --max-pages 200 --database /home/golkonst/src/LexRadar-web-control/.control-center-state/RUN/parser.sqlite --output /home/golkonst/src/LexRadar-web-control/.control-center-state/RUN/parser.csv
```

Над ней работает `control_parser_runner.py`: отдельная process group и наблюдение
за владельцем. `shell=True` не используется. Строго один исполняющий поток.
N — новые пригодные уникальные сайты, а не просмотренные карточки. Новая БД
гарантирует отсутствие накопленных лидов от предыдущего запуска. MedAdvisor —
медицинские клиники; остальные отрасли, включая стоматологию, — Orgpage.
География всей России, без city/region/start-page/resume.
Ограничения: `max(200, 10 × N)` карточек, 200 страниц, общий таймаут 4 часа.

Фактический контракт Parser сильнее наличия контакта, но слабее подтверждения
официальной юридической принадлежности: требуются название, сайт и телефон
либо email; сайт available либо подтверждённая защитная страница captcha/blocked.
Явный mismatch бренда исключается, unknown/probable допускаются. Строительство
дополнительно проверяет конечный домен и тематику. Рейтинг не ограничивает приём.
Эти различия видны перед подтверждением; контакты не проверяются звонком/письмом.
Первичный скрининг главной страницы уже выполняется самим Parser без платного API.

Выход внутри RUN: `parser.sqlite` (возможно WAL/SHM), `parser.csv` (UTF-8 BOM,
`;`), `parser.summary.json`, временные файлы браузера. HOME/TMPDIR направлены
в RUN, `-B` запрещает pycache в исходниках. Окружение не наследует ключи API,
cookies и токены; передаются только системные параметры и DISPLAY/XAUTHORITY
для оконного браузера. SQLite панели хранит params/result и ограниченный журнал
stdout/stderr, отдельного неограниченного файла лога нет. В журнале маскируются
поля авторизации/ключей/cookies/паролей и URL с user:password.

Успех требует exit code 0, корректную сводку с target_achieved=true,
exported_total и ровно N импортированных пригодных уникальных сайтов.
Недобор при exit code 0 остаётся `failed`, stop_reason и число пригодных видны.
Частичные/отменённые результаты остаются на диске, но не публикуются как успешный
экспорт. Скачивание `/exports/<id>` только для успешного задания, через безопасное
открытие без symlink; CSV формируется для просмотра в таблицах с защитой формул
(апостроф перед =/+/-/@). Исходный CSV не меняется. Максимум выдачи — 8 МБ.
Индекс запусков ограничен последними 64 успешными запусками, 32 МБ CSV и
20 000 лидами; превышение даёт предупреждение. Исторический импорт отдельно.
Повторные организации в разных запусках не сливаются.

Отмена/таймаут посылают SIGKILL только созданной process group, включая Chromium.
При аварийном исчезновении панели supervisor завершает ту же группу. Это резкая
остановка: итоговый CSV не гарантирован, оставшуюся БД не возобновляем автоматически.
Сервер и чужие PID не используются как цели отмены. После перезапуска running
становится failed, queued — cancelled. Сетевой сбор сам не возобновляется.

### Диагностика и текущая готовность

`/settings`: отдельные пути источников только для чтения, состояние и доступность
записи, Python/Chromium cache, проверка исходников, Playwright 1.63.0 и наличия
Chromium. Проверка запускает только локальный driver Playwright, без браузера,
без обращения к источникам; максимум 10 секунд. Диагностика повторяется при
подтверждении и перед выполнением очереди.
На 29.10.2026 в `.venv` найдены Playwright 1.63.0 и Chromium; MedAdvisor проходит
локальную диагностику. Это не подтверждает доступ сети, библиотек ОС при запуске
браузера или отсутствие CAPTCHA — реальный сбор не проводился.
Orgpage использует `headless=False`; при отсутствии DISPLAY запуск заблокирован
с причиной. DISPLAY должен быть доступен процессу панели и поддерживать авторизацию
X11; непустая переменная сама по себе не доказывает работоспособность дисплея.
Никакие изменения парсера для обхода этого ограничения не внесены.

Отдельная задача скрининга выбранных лидов не включена. Изучен существующий
`lexradar batch-screen <urls-file> --output <directory>`: это ограниченный
бесплатный первый проход, но он создаёт собственные process sessions.
Текущая отмена группы Parser не охватывает такие отделённые worker-процессы;
без отдельной интеграции lifecycle подключать его небезопасно. Сбор Parser
уже сохраняет свой ограниченный скрининг. Платный GPT, массовый аудит, PDF,
CRM-запись и письма не подключены.

SQLite хранит журнал атомарно; flock исключает второй исполнитель.
После перезапуска running становится failed с причиной, queued — cancelled;
автоматического возобновления нет. Ctrl+C отменяет активное и ожидающие задания.
Лимит: 100 ожидающих/активных и 1000 сохранённых заданий; старые не удаляются
автоматически. При достижении лимита новая постановка отклоняется.

POST `/collect/preview`, `/collect`, `/jobs/preview`, `/jobs`, `/jobs/<id>/cancel`, `/refresh` требуют случайный
токен текущего процесса, явный checkbox-подтверждение, допустимые Host/Origin,
форму URL-encoded не более 16 КиБ. Токен меняется при перезапуске.
Отклоняются чужие Host (защита от DNS rebinding), Origin, chunked-тела.
Нет CORS. Ответы содержат no-store, nosniff и ограничительную CSP.
Локальный сервер без пользовательской авторизации: не публиковать наружу
и не предоставлять недоверенным локальным приложениям доступ к нему.

## CRM preview

Полностью прочитаны оба справочника EspoCRM. Схема, экспортёр, постоянный
CRM-журнал и шаблоны не менялись. Ни один CRM API не вызывается.
`/crm` читает только `*crm-result.json` в разрешённом дереве результатов,
ожидает массив сохранённых результатов CRM_PREPARE_ONLY. Показываются
id, status, identity.company_name, account_id, materials[].document_id,
источник и mtime; произвольные поля и секреты не публикуются.
Записи требуют проверки; PENDING_REVIEW не является разрешением отправки.
«Не отправлено панелью» не утверждает состояние внешней CRM или почты.
Кандидаты Parser v3 доступны отдельно, без имитации готовых CRM-записей.

Постоянные журналы из домашнего каталога, .env и скрытые приватные архивы
не сканируются. Для просмотра сохранённых результатов из другого места
укажите их родительский каталог через --results-dir. Нет загрузки файлов
в CRM и кнопок отправки.

## Индекс и ограничения

Снимок индекса общий для страниц, защищён блокировкой. Не чаще раза в пять
секунд сканируются имена/размеры/mtime; содержимое перечитывается только при
изменении сигнатуры либо POST «Перечитать индекс» в настройках. Добавление,
удаление и изменение файлов учитываются; публикация через атомарное
переименование рекомендуется. Изменение содержимого с сохранением размера
и mtime требует ручного перечитывания. Снимок может отставать до пяти секунд;
файл перед выдачей заново открывается безопасным способом.

Ограничения видны общим счётчиком предупреждений; при его наличии счётчики
главной относятся только к доступной части архива. Файлы за лимитом не считаются
отсутствующими во всём проекте. Для большого архива выберите конкретный запуск.

- Общий обход каждого корня: глубина 8, 512 каталогов, 20 000 записей каталогов,
  1024 подходящих файла; до 64 МБ JSON для отчётов и CRM.
- Parser: глубина 2, 64 каталога, 2048 записей в каталоге/4096 суммарно,
  128 экспортов, 8 МБ на файл, 32 МБ суммарно, 20 000 лидов.
- Упоминания: 128 каталогов, глубина 8, 8 МБ на файл/32 МБ суммарно,
  20 000 упоминаний. Лимит исторического адаптера сохранён.
- PDF в карточке упоминания/аудита: до 2048 записей каталога и 64 PDF.
- CRM preview показывает первые 200 найденных результатов и общий счётчик.

Скрытые каталоги, examples, tests, docs, node_modules и __pycache__ исключены.
Символьные ссылки не читаются. Каждый компонент пути при выдаче открывается
через dir_fd/O_NOFOLLOW, запрещены абсолютные пути, `..`, FIFO и escape через
замену каталога ссылкой. HTTP принимает ID-хеши, а не пользовательский путь.
HTML экранируется; кликабельные внешние сайты допускают только HTTP(S).

## Проверки

```bash
python3 -m unittest discover -s tests -p 'test_control*.py' -v
python3 -m py_compile control_*.py tests/test_control*.py
git diff --check
```

HTTP проверяется in-memory handler, задания — настоящими дочерними процессами
на временных фикстурах и подменёнными фиксированными командами для отмены,
таймаута и ошибок. Порт 8080 не используется. В текущей песочнице bind на
временный localhost-порт запрещён (PermissionError errno=1); браузерная
проверка после ручного перезапуска остаётся пользователю.
