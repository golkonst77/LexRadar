# LexRadar Control Center

Локальный сервер на стандартной библиотеке Python, только чтение.
Перезапуск: остановите прежний процесс через Ctrl+C и выполните:

```bash
cd /home/golkonst/src/LexRadar-web-control
python3 control_center.py --parser-dir /home/golkonst/lexradar-data --results-dir /home/golkonst/src/LexRadar-compact --port 8080
```

Откройте http://127.0.0.1:8080/organizations. Сервер слушает только 127.0.0.1.
Пакет LexRadar и дополнительные зависимости не нужны. Это локальный сервер
без авторизации, не предназначенный для публикации в интернете.

## Источники Parser v3

`/organizations` по умолчанию показывает только лиды Parser v3.
`--parser-dir` по умолчанию равен `/home/golkonst/lexradar-data`.
При проверке 29.10.2026 обнаружены реальные данные:

- `/home/golkonst/parser-smoke-20261029/clinics.csv`: 24 колонки, одна запись;
- `/home/golkonst/lexradar-data/parser-c8e0008cfad0538c9b5703f7c9e5ea76845e52d582788c06942d8c3ab3368b9f/`:
  исходный `parser.csv` и производный `crm-candidates.json` из `parser_import.py`.

В самом `/home/golkonst/src/LexRadar-compact` пригодных экспортов при поиске
не обнаружено; один архивный каталог недоступен по правам. Внешний handoff доступен.
Для просмотра непосредственно исходного CSV используйте
`--parser-dir /home/golkonst/parser-smoke-20261029`.
Новые реальные экспорты размещайте в выбранном каталоге либо его подкаталогах
глубиной до двух уровней. Контрольный центр сам ничего не импортирует и не записывает.
Публикуйте готовые экспорты атомарным переименованием, чтобы запрос не читал
файл во время его перезаписи.

Поддерживаемые фактические схемы, UTF-8 с BOM или без него:

- CSV с разделителем `;`, обязательные заголовки: `Организация`,
  `Официальный сайт`, `Телефон`, `Email`, `Исходная карточка`.
  Остальные исходные колонки сохраняются в карточке. `Статус скрининга`
  отображается только при наличии значения; `ИНН` используется, если он есть.
- `crm-candidates.json`: массив объектов с `company_name`, `website`, `phone`,
  `email`, `source_card`; сохранённый `crm_status` отображается при наличии.
  Это локальное значение файла, состояние CRM по API не проверяется.
  Поле `inn` используется, если оно присутствует.

Соседний `parser.csv` имеет приоритет над производным JSON, чтобы один handoff
не показывался дважды. Повреждённый CSV не заменяется потенциально устаревшим JSON.
`lexradar.csv` (вход аудита) и `results.csv` не являются экспортами лидов и пропускаются.
Произвольные JSON, массивы упоминаний и тестовые фикстуры не служат запасным источником.
Пустые данные дают пустую страницу без демонстрационных лидов.

Таблица и карточка показывают название, официальный сайт, ИНН при наличии,
телефон, email, исходную карточку агрегатора и сохранённый статус обработки.
Официальный сайт берётся исключительно из соответствующего поля экспорта:
только HTTP(S), без credentials и пробелов. Ссылка агрегатора, бренд, URL аудита
и цитаты не подставляются вместо сайта. Пустой email не заполняется автоматически.
Карточка содержит относительный путь файла, номер записи (с 1, без заголовка CSV)
и исходную запись. ID карточки зависит от относительного пути и содержимого записи:
перестановка строк не перенаправляет старую ссылку на другую организацию;
изменение контактов или перемещение файла меняет ссылку. Разные экспорты
не объединяются автоматически.

Поиск `q` нечувствителен к регистру: подстрока названия, официального сайта,
ИНН, телефона или email. Телефоны ищутся в сохранённом написании.
`status` фильтрует точное сохранённое значение. Страницы по 20 записей,
параметры фильтра сохраняются. Пустой результат поиска явно обозначен.
Пример: `/organizations?q=clinic&status=review&page=2`.

## Упоминания и аудиты

`/mentions` — отдельный список упоминаний организаций из первичного аудита.
Он читает `--results-dir` (по умолчанию текущий рабочий каталог):
`audit.json` с `schema_version=primary-audit-0.1` и массивом `organizations`,
либо `organizations.json` с `audience=internal_only` и массивом `rows`.
При соседстве используется только `audit.json`.
Четыре организации, упомянутые на kaluga-med.ru, остаются упоминаниями;
они не попадают в `/organizations`.
Сайт проверенного ресурса выводится в прежнем разделе только при одной организации;
URL из `identification_sources` не считаются официальными сайтами.

**Автоматической привязки аудита/PDF к лиду нет.** Найденные файлы не дают
подтверждённой связи юридического лица с аудитом. Даже совпадающий домен и
соседний PDF не разрешают выдачу из карточки лида. Карточка явно сообщает,
что подтверждённой связи нет. Поддержка связывания по проверенному идентификатору
или нормализованному домену с проверкой неоднозначности остаётся отдельной задачей.

Прежние наблюдения, гипотезы, этапы, цитаты и PDF доступны только в `/mentions/<id>`.
Они относятся к проверенному сайту; принадлежность проблемы каждой упомянутой
организации не установлена. Готовые `proposal.pdf` и `proposal-*.pdf` читаются
только непосредственно рядом с результатом; это связь по каталогу результата,
а не подтверждённый адресат предложения. `/documents/<id>/<document-id>` открывает
PDF, `?download=1` скачивает его. PDF не генерируются.

## Ограничения и безопасность чтения

Поиск Parser ограничен двумя уровнями подкаталогов, 64 каталогами,
2048 записями на каталог (4096 суммарно), 128 файлами экспорта, 8 МБ на файл и 32 МБ чтения
на запрос. Превышение лимита даёт предупреждение; выберите меньший каталог.
Новые и изменённые файлы читаются при обновлении страницы, кэша нет.
Архив упоминаний ограничен 128 посещёнными каталогами и глубиной 8;
для большого архива указывайте конкретный запуск через `--results-dir`.
Ошибки, неподдерживаемые форматы и ограничения отражаются общим предупреждением
без абсолютных путей и содержимого файлов.

Каталоги `examples`, `tests`, `docs`, `node_modules`, `__pycache__` и скрытые
каталоги исключены из обхода. Символьные ссылки не читаются, включая компоненты
пути корня. Каждый путь при чтении открывается через дескрипторы с `O_NOFOLLOW`.
Нужен Linux/POSIX с `os.fwalk` и `dir_fd`. Произвольного файлового маршрута нет.
HTML экранируется, ссылки из данных выводятся текстом.

Для PDF сохранены ограничения: 50 МБ, обычный файл, заголовок `%PDF-`,
запрет абсолютных относительных путей, `..`, FIFO и символьных ссылок.
Клиент передаёт хеш документа, а не путь. Удалённые или недоступные документы
возвращают 404. Ответ содержит `application/pdf`, `nosniff`, `no-store` и
`Content-Disposition`. Проверка заголовка не проверяет содержимое PDF.

Другие маршруты: `/` — главная, `/health` — доступность процесса,
`/api/status` — режим `read_only`, анализ и рассылка отключены.
Неизвестные ID и маршруты возвращают 404. Парсер, анализ, сеть, CRM,
рассылка, SQLite и генерация PDF не запускаются. Результаты не изменяются.

Проверки без сокета и внешних сервисов:

```bash
python3 -m unittest discover -s tests -p 'test_control*.py' -v
python3 -m py_compile control_center.py control_leads.py control_organizations.py control_results.py tests/test_control_center.py tests/test_control_leads.py
git diff --check
```
