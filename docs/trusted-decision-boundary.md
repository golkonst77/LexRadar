# Реальное решение и демонстрационный Gateway

`lexradar.decision.decide_production` — единственный интерфейс реального решения.
В текущем MVP он **всегда возвращает HOLD / not_confirmed**. Реестр не умеет
удостоверять происхождение нормативного текста, а локальные записи рассмотрения
не удостоверяют личность и полномочия проверяющего. Доверенного основания для GO
пока получить нельзя. Это намеренное ограничение, а не имитация экспертизы.

Поля `reviewer_kind=human`, `identity_verified`, `evidence_checked`,
`legal_basis_checked`, импортированный `verified_issue`, совпадение A/B и confidence
не создают доверия. Даже корректный по схеме VerificationReport — импортированное
утверждение. Decision не вызывает Gateway, аудиторов, Verifier, сеть или LLM.

## Локальный workflow

```sh
lexradar review-decision examples/analysis-dossier \
  --finding examples/decision-finding.json \
  --registry examples/legal-registry.json --output work/review

lexradar decide examples/analysis-dossier \
  --finding examples/decision-finding.json \
  --registry examples/legal-registry.json --output work/decision.json
```

Для существующего клиентского текста добавляется `--client-text PATH`, для
сопоставляемого импортированного отчёта — `--imported-report PATH`. Эти параметры
должны совпадать при подготовке и проверке рассмотрения. Команда ничего не генерирует
для клиента. Выходные пути должны быть новыми; исходные файлы не изменяются.

`review-decision` создаёт binding.json и **неутверждённый** review.json: пустые
проверяющий и обоснование, время null, все проверки false. Человек может заполнить
локальную запись и передать её в `decide --review work/review/review.json`.
Это сохраняет будущий workflow, но даже полностью заполненная запись остаётся
`untrusted`, `origin_authentication=unsupported`, `authenticated=false`.
Самостоятельное изменение этих полей на trusted/true отклоняется.

## Привязка и целостность

ReviewBinding включает SHA-256 точных байтов:

- исходного collection.json;
- проверяемой находки JSON;
- всего реестра нормативных оснований JSON, включая текст, редакцию, периоды действия;
- существующего клиентского текста, включая переводы строк и Unicode;
- импортированного отчёта, если он передан.

Дополнительно хешируется инвентарь артефактов с evidence ID, путями, типами,
размерами и хешами. Реальные файлы досье проверяются существующим валидатором;
хеш каждого нормативного текста сверяется с его содержимым. Отсутствующий
клиентский текст отличается от пустого файла. Любое изменение пакета требует новой
записи рассмотрения: прежняя получает `invalidated`, в том числе при согласованной
подмене файла и его хеша в manifest. Отсутствующие файлы, симлинки, неверные размеры,
дублирующиеся ключи JSON и неподдерживаемые ссылки на evidence закрывают проверку.

Хеш доказывает только совпадение локальных байтов. Он не доказывает происхождение
сайта, официальность текста, действительность нормы, истинность наблюдения или
человеческое рассмотрение. Файлы не становятся подписанными или неизменяемыми.
Decision не является удостоверенным документом; потребитель должен вызывать API
заново, а не доверять вручную отредактированному выходному JSON.

## Два вида завершённости

`technical_processing_completed=true` означает, что локальная проверка пакета
завершилась. Это возможно при отсутствующем/недоверенном рассмотрении и при
несовпадении его binding. `legal_research_completed=false` сохраняется всегда.
Недоступность исходной страницы не подменяется нарушением: она остаётся ограничением.

CLI возвращает 0 при выполненной технической обработке даже с HOLD; код 0 не
означает юридического допуска. При непроверяемых входах сохраняется HOLD с
technical_processing_completed=false и возвращается 1.

## Legacy и benchmark

`decide_demo` / `build_demo_report` сохраняют старые правила v0.1, включая условный
GO. Совместимые имена `gateway.decide` и `report.build_report` — их legacy-алиасы.
`lexradar demo examples/input.json` явно запускает демонстрацию; старая команда
`lexradar examples/input.json` сохранена с предупреждением. Вход и результат имеют
scope legacy_demo, production_go_allowed=false и client_release_allowed=false.
Черновик помечен DEMO/LEGACY. Это не реальный допуск клиенту.

Синтетический benchmark отмечает scope synthetic_or_replay_only. Его положительные
метрики — проверка гипотез на фикстурах, а не подтверждённые нарушения. Для случаев
с находками дополнительно сохраняется production-decision.json с HOLD; случаи без
находок не объявляются проверенными юридическими решениями.

Автоматическая отправка недоступна для обоих интерфейсов, включая demo после
ручного флага approved. Авторизация, электронные подписи, доверенная аттестация
источников и процедура выхода из HOLD требуют отдельной будущей реализации и
проверки; этот PR их не моделирует.
