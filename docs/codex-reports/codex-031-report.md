## Реализовано

`lexradar compact-analyze` принимает `--mode offline|openrouter` (offline по умолчанию), `--ledger`, `--approval`, `--allow-external-transfer`, `--dry-run`, `--sector`. Paid требует постоянный ledger, явное разрешение передачи, ручное подтверждение точного SHA-256, успешный screening и подтвержденный профиль. CLI сообщает безопасную ошибку без traceback/содержимого конфигурации. Offline использует прежний встроенный fake transport.

`compact-preview.json` содержит байты пакета, SHA-256, число форм/организаций, coverage, ограничения чтения, категории screening и резерв. Терминал показывает размер, SHA, количества, категории и резерв, без совпавших чувствительных значений. Dry-run не создает provider, не читает API-ключ, не вызывает transport и не записывает ledger/lock; проверяет существующий ledger только чтением. `dry_run_ready` относится к перечисленным техническим проверкам, не подтверждает наличие ключа, баланс аккаунта или доступность маршрута.

Screening обязателен независимо от approval. Исправлены ложные совпадения внутри SHA-256, служебного словаря имен полей и слова «первичные». Все значения body и dictionary, включая неиспользуемые элементы dictionary, продолжают проверяться. Email, телефоны, ФИО и медицинское содержимое не получили исключений. Повторная подготовка и авторизация перед резервированием проверяют изменение исходников/пакета. Передается неизменяемый снимок, а не повторно читаемый сетевым transport файл. Ledger запрещен внутри исходного досье/output, поверх approval и через symlink.

Сохранены `HOLD`, `not_confirmed`, запрет клиентского выпуска. Нет автоматического GO, увеличения бюджета, retry или смены модели. Повторный ручной запуск учитывает тот же ledger сайта. Pending/unknown/overrun запрещают дальнейшие расходы; timeout сохраняет полный резерв. Известная стоимость сверх резерва записывается полностью и блокирует дальнейшие запросы. Dry-run с исчерпанным ledger блокируется без изменения файла. Реальный reserve выполняется под файловой блокировкой перед transport; предварительный просмотр не заменяет эту проверку.

## Модель и официальные источники

Проверены только публичные GET, без авторизации и досье:

- [OpenRouter model catalog](https://openrouter.ai/api/v1/models): `deepseek/deepseek-v3.2`; reasoning `mandatory=false`, `default_enabled=false`.
- [OpenRouter endpoint metadata](https://openrouter.ai/api/v1/models/deepseek/deepseek-v3.2/endpoints): закрепленный маршрут `deepinfra/fp4`, input **$0.26/M**, output **$0.38/M**, context **163840**, max completion **16384**; поддерживает `max_tokens`, `reasoning`, `response_format`, `structured_outputs`.
- [Reasoning controls](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens): для отключения отправляется `reasoning.enabled=false`; `exclude` лишь скрывает reasoning и не освобождает от оплаты. Reasoning относится к output.
- [JSON/structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs): возможности зависят от модели/маршрута. Используется `json_object`, инструкция JSON в system и локальная строгая проверка схемы/цитат; JSON mode сам по себе не гарантирует корректную схему или юридические выводы.

Минимальная отображаемая цена модели не равна цене JSON-совместимого маршрута: дешевый GMICloud в проверенных metadata не объявляет `response_format`. Поэтому его тариф не используется для резерва. Нельзя считать выбранную модель самой дешевой среди всех актуальных DeepSeek; это проверенная недорогая модель с подходящим маршрутом.

Профиль в `compact_profile.py` строго фиксирует модель, цены, один auditor, retries=0. Provider получает `only=[deepinfra/fp4]`, `allow_fallbacks=false`, `require_parameters=true`, `max_price` и `reasoning.enabled=false`. Ответ с другим model отвергается. Конфигурация: `examples/compact-openrouter-config.json`, output 2000 токенов, бюджет $0.05. Подтверждение тарифов действует **до 2026-10-15 00:00 UTC**; затем paid блокируется до новой проверки официальных источников и обновления профиля. Dry-run никогда не обновляет metadata через сеть. Недоступность маршрута не вызывает fallback.

## Dry-run и стоимость

Синтетический пример, не клиентское досье:

```bash
lexradar compact-analyze examples/primary-audit/dossier \
  --output /tmp/lexradar-031-dry \
  --config examples/compact-openrouter-config.json \
  --as-of 2026-10-10T00:00:00+00:00 \
  --mode openrouter --dry-run
```

Результат: `dry_run_blocked`, HOLD, расход $0, резерв **$0.01171874**. Пакет **39901 bytes**, **2 формы**, **2 организации**, SHA-256 `3925b72aeeb38df69db5eaba97d7b5b488c5a6d22c926a10f82b9e9073c2808a`. Пример содержит блокирующую категорию `identity_or_health_context`; также отсутствуют разрешение, ledger и действительное approval. Причина первого неуспешного gate записана в `blockers`; screening-категории доступны независимо от него. Exit code 1 означает блокировку, а не выполненный запрос.

Суммируются **system 1224 bytes + user 39901 bytes + 1024 framing** = **42149** консервативных input tokens. Резерв: `(42149 × 0.26 + 2000 × 0.38) / 1000000 = $0.01171874`. Это верхняя оценка по UTF-8 bytes, не обещание точной токенизации/фактической стоимости. Cache discount не учитывается. При максимальном пакете 40000 bytes и том же prompt/output резерв $0.01174448, ниже цели $0.05. Лимит одного сайта никогда не выше $0.50; новый запуск не увеличивает сохраненный лимит. Нарушение тарифного контракта провайдером невозможно отменить локально: обнаруженный перерасход сохраняется и дальнейшая оплата блокируется.

Для разрешенного пилота сначала надо локально проверить `packet.json`, создать отдельный approval с exact SHA, `approved=true`, `contents_reviewed=true`, непустым reviewer и прошедшим aware timestamp; затем повторить dry-run с `--ledger /path/site-budget.json --approval /path/reviewed-approval.json --allow-external-transfer`. Непроверенные шаблоны approval сами по себе не разрешают transfer. Output каждого запуска должен быть новым каталогом вне досье. API-ключ берется только из `OPENROUTER_API_KEY` для реального режима; здесь его не использовали.

## Оставшиеся препятствия: BLOCKED

Технический путь проверен fake transport; первый реальный платный пилот пока **BLOCKED**. Нет отдельно проверенного безопасного публичного пакета, действительного approval и разрешения на его передачу. В используемом синтетическом примере screening сохраняет блокировку. API-ключ, средства аккаунта и доступность закрепленного маршрута не проверялись; после срока действия нужна повторная публичная верификация профиля. Реальный JSON ответ/учет стоимости не проверены платным запросом по условиям задания. Ledger использует Unix `fcntl`; Windows не подтвержден.

Если публичные юридические реквизиты блокируются длинными числовыми шаблонами, предлагается отдельная структурированная категория **проверенных реквизитов юридического лица**: независимая проверка источника/контрольных цифр и типа организации, ограничение только конкретным полем ИНН-10/ОГРН-13 и exact SHA новой версии пакета. Свободный текст, ИНН физлица/ИП, телефоны и медицинские данные должны оставаться под общим screening. Такое исключение в этом задании не реализовано; широкого allowlist и флага отключения screening нет. Безопасный текущий путь — локально удалить/редактировать необязательные чувствительные сведения и снова подготовить, проверить и подтвердить новый пакет.
