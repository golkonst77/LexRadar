## 5. Фактические связи компонентов

### 5.1. Рабочий MVP

```text
lexradar mvp → mvp.run
  → collect ИЛИ проверка/копирование сохраненного dossier
  → config: synthetic/compact-a, single_auditor=True
  → analyze_compact(mode=offline)
      → prepare / primary audit / packet / preflight
      → CompactFakeTransport → validate_compact
      → production_outcome=HOLD, client_release_allowed=False
  → при analysis.status == success: render_mvp → proposal.html
  → audit_documents.generate → audit.txt / audit.html / опционально audit.pdf
  → run.json / sha256.json
```

Условие `success` означает техническую валидность анализа. Проверки `GO` перед `render_mvp` нет. `mvp.run` не вызывает `auditors.orchestrator.analyze`, `disagreements.compare`, `verifier.start/finish` или `decide_production`.

### 5.2. Отдельный общий A/B-путь

```text
досье → load_packet → analyze
  → messages_for(A, packet) → provider.complete(auditor_a)
  → messages_for(B, packet) → provider.complete(auditor_b)
  → validate_result каждого результата → compare(A, B)
  → analysis.json / requests.jsonl / run.json
```

Это готовая инфраструктура анализа, а не соединенная коммерческая цепочка. OpenRouter-режим требует разрешения передачи и утверждения точного пакета; offline использует заглушки. Общий и compact пути имеют разные форматы результатов — простая замена вызова без адаптации потребителей недостаточна.

### 5.3. Пакет №46

```text
сохраненное досье №45 + primary.local.json + редакторский brief
  → review_bundle.build
  → проверка оригиналов и цитат / группировка форм
  → review.json(client_release=HOLD)
  → proposal.html + audit.html + evidence.html + sha256.json
```

Brief определяет выбор и коммерческую формулировку. Проверка присутствия цитаты не доказывает автоматически, что весь редакторский текст логически следует из нее. Текущий слой полезен для внутреннего просмотра, но не заменяет проверку сгенерированного КП и согласование специалистом.

## 6. Независимость аудиторов

**Что подтверждено кодом и безопасной проверкой:**

- `analyze` загружает единый пакет один раз и строит каждый запрос через `messages_for(auditor, packet)`; входного параметра результата A у B нет.
- Каждый контекст содержит ровно system + user, общий user payload и разные версии system prompts. Ответы и ошибки A не добавляются в сообщения B; повторные попытки используют свежие словари сообщений.
- Последовательное выполнение само по себе не нарушает независимость контекстов. Общие бюджет и экземпляр provider не являются передачей результата A в B; штатный OpenRouter-адаптер формирует отдельные HTTP-запросы.
- На обоих сохраненных досье в №47 проверены равенство user payload A/B, различие system prompts и отсутствие общей изменяемой записи: изменение сообщения A в памяти не меняет B.
- Существуют тесты `test_independent_context_and_no_go`, `test_retry_is_fresh_and_b_does_not_receive_a`, `test_invalid_a_does_not_prevent_independent_b`, `test_no_shared_mutable_messages`, `test_same_model_is_declared` в `tests/test_auditors.py`.

**Что не подтверждено или отсутствует:**

- Эти тесты полного оркестратора заново не запускались: их fixtures создают файлы. Проверка №47 касается формирования сообщений и чтения реального локального досье, а не двух сетевых inference.
- В MVP нет второго аудитора вообще. `compact_pipeline` выполняет только A.
- В `examples/compact-openrouter-config.json` оба поля модели равны DeepSeek, при этом `single_auditor=true`; B фактически не вызывается. Общий `examples/openrouter-config.json` содержит placeholders, не действующую пару.
- Контракт `AnalysisConfig` не требует DeepSeek для A и Qwen для B и не запрещает равенство model IDs. Равенство только отражается в `same_model_independence_limited`.
- Изоляция запросов не доказывает независимость обучающих данных, отсутствие коррелированных ошибок или юридическую точность. Совпадение A/B не должно самостоятельно давать GO.

Итог: **механизм изоляции A/B реализован; обязательная независимая пара DeepSeek/Qwen и ее участие в сквозной цепочке отсутствуют**.
