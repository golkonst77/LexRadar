## Механизм закрытия unknown

`SiteBudget.preview/reserve` блокируют любые состояния кроме known, даже при
достаточном остатке. `settle` принимает только pending: повторный вызов для
unknown выдаёт Reservation already settled. Безопасного штатного административного
перехода unknown → known с доказательствами ранее не было.

Добавлен отдельный `src/lexradar/auditors/reconciliation.py`:

- `propose` проверяет generation/request/model/provider и конечную неотрицательную
  стоимость из metadata, требует имя проверяющего и состояние unknown;
  возвращает предложение без записи ledger.
- Предложение содержит SHA256 ledger и metadata, прежнюю запись с резервом,
  идентификаторы, время, проверяющего, стоимость, finish_reason и result_usable=false.
- `apply_reviewed` — отдельная административная функция, вызываемая только явно
  после проверки предложения человеком. Берёт штатный ledger lock, отвергает
  устаревшее/повторное предложение; сохраняет исходный резерв и аудиторскую запись
  внутри той же записи, атомарно штатным write с fsync. Превышение резерва
  переводит запись в overrun и сохраняет блокировку дальнейших расходов.

**К существующему ledger ни одна из этих операций записи не применялась.**
Автоматического вызова reconciliation из платного pipeline или скрипта нет.
Это механизм учёта стоимости, а не признания качества/успеха ответа.
Доказательства metadata нужно сохранить отдельно и проверить их происхождение;
хеш удостоверяет неизменность файла, но сам по себе не удостоверяет данные API.

окончание чтения по HTTPResponse/Content-Length, обнаружение преждевременного
EOF, поддержка chunked/close-delimited framing, безопасная диагностика,

Историческая точная причина transport_error остаётся неизвестной.

Настройки: deepseek/deepseek-v3.2, only=[siliconflow/fp8], fallbacks=false,
require_parameters=true, max_price prompt=0.259/completion=0.80 USD/M,
reasoning.enabled=false, response_format=json_object, max_tokens=2000,
single_auditor=true, retries=0. Timeout=30 секунд, max_response_bytes=1000000.
Transport ограничивает оставшееся время чтения общим deadline; timeout не
гарантирует отмену upstream-работы или отсутствие списания. Автоповтора нет.

Фактический payload к OpenRouter содержит **stream=false**. Сведения первой
попытки о streamed=true не позволяют заключить, что клиент запрашивал или получил
SSE: локальные артефакты не содержат сохранённого запроса и ответа той попытки.
Chunked HTTP framing не равно SSE streaming. Новый transport дополнительно
отвергает stream=true; SSE-парсер не добавлялся.

## Скрипт второго пилота

`scripts/run_paid_pilot_042.py` по умолчанию только проверяет подготовку локально.
`--metadata` допускает ровно один read-only GET и сохраняет отдельный приватный
metadata/proposal_unreviewed. До GET создаётся постоянный O_EXCL-маркер с fsync;
повторная такая команда блокируется даже после сетевой ошибки. Не удалять маркер
для повторения; при необходимости отдельно разбирать причину.

Будущий `--execute --approval PATH` требует отдельно предоставленный человеком
approval: штатные packet_sha256, approved, contents_reviewed, reviewer,
approved_at и дополнительные поля pilot_id="042", site_limit_usd="0.05",
previous_generation_id с указанным выше ID. Старый approval-038 отвергается.
Файл не создаётся этим заданием. Передача `--execute` в этом задании запрещена
пользователем и не выполнялась.

Платный путь проверяет ровно первую запись с known, cost=0.002864425 и audit
reconciliation, удерживает flock, выполняет два локальных dry-run с новым
approval, свежие endpoints/key/credits GET и GET первой генерации для проверки
ID/request_id/стоимости. Штатный pipeline ещё раз проверяет профиль/approval,
атомарно резервирует общий бюджет в прежнем ledger. Непосредственно перед POST
SecondOnceTransport проверяет stream=false и все ограничения №39, создаёт
`work/second-pilot/attempt-042.json` через O_EXCL с fsync; допускается один POST.
После ошибки/тайм-аута/перезапуска маркер остаётся. Pending/unknown в ledger
также блокируют повтор. Старые attempt-039, approval и отчёты не заменяются.

В текущем sandbox создание `work/second-pilot` отклонено правами доступа;
защиты не обходились. Локальный dry-run работает без записи в work.
Сетевые режимы следует выполнять в обычном окружении владельца репозитория;
при ошибке доступа скрипт останавливается до POST.
