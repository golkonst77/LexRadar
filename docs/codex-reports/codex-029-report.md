## Реализация

`src/lexradar/primary/compact.py` и команда `lexradar compact-preflight`:

- Вызывают существующий `primary.audit_saved_dossier()`. Локальный лимит чтения остаётся 2 МБ и не подменяется лимитом 40 КБ.
- Формируют канонический UTF-8 JSON `compact-primary-v1`: сортировка ключей, без пробелов сериализации, обязательное явно заданное время оценки. Одинаковые досье, версия кода, сектор и дата дают одинаковые пакет и SHA-256.
- Сохраняют все 13 этапов, coverage, организации и неопределённость их ролей, формы/поля/согласия/политики, наблюдения, гипотезы, проверки, статические декларации и ограничения. Полнота HTML и PDF не повышается.
- Дедуплицируют повторяющиеся строки, списки и объекты. `$` означает ссылку в dictionary, числовые ключи раскрываются через keys. `unpack()` восстанавливает body. Это JSON-представление, а не обрезка сериализованного текста.
- Заменяют site citation на excerpt ID. Выдержка содержит evidence ID, URL, basis, quote, PDF page и static span. Полный citation с artifact path/hash остаётся в локальном trace map.
- Проверяют оригиналы loader и primary, затем цепочку sent excerpt → local trace → оригинал: URL, принадлежность artifact/hash, дословную цитату в воспроизведённом тексте страницы PDF либо в диапазоне сохранённого HTML. `verify_quote()` отклоняет цитату, которой нет в конкретной отправленной выдержке.
- Не передают бинарные артефакты. `omissions` явно перечисляет только локальные коммерческие предложения/обоснования работы, inventory артефактов и метаданные скриншотов. Всё это остаётся в полном primary. Факты и ограничения не удаляются ради размера.
- При размере более **40 000 байт**, включая словари, возвращают `PacketOverflow` со статусом `packet_overflow/review_required`. CLI возвращает код 2 без создания пакета. Автоматических чанков нет.
- `preflight()` повторно строит пакет и сравнивает snapshot до записи. `approve()` повторяет проверку и вызывает существующий `authorize()` для подтверждения именно compact SHA-256. Approval полного Collector-пакета не используется.
- Screening применяется к окончательному JSON, включая строки dictionary. Он не отключён; approval не обходит подозрения. В preflight пишутся только категории и расположения, без найденных значений.
- Сохраняют HOLD/not_confirmed и запрет клиентского выпуска. Новый путь не вызывает провайдер, B или verifier.

Выходные файлы: `packet.json`, `preflight.json`, неподтверждённый шаблон `approval.json`, `primary.local.json`, `trace-map.local.json`. Каталог должен быть новым, вне досье, без симлинков. Все результаты содержат данные досье и должны оставаться локально; в PR их нет.

## Расходы и ограничения

Новая команда не делает платных запросов, её API-расход равен нулю. Следующий этап должен использовать существующий OpenRouterProvider, включая DeepSeek через OpenRouter. Новый DeepSeek adapter не создавался.

Будущий резерв должен включать system+user+output, например по существующей формуле:

`R = ((bytes(system) + bytes(user) + 1024) × P_in + max_output_tokens × P_out) / 1_000_000`.

Расчётный пример, **не проверенный тариф**: caps 0.30/1.20 USD за миллион, system ≤ 4000 байт, user ≤ 40 000 байт, output ≤ 4096 токенов: `(45024 × 0.30 + 4096 × 1.20) / 1e6 = 0.0184224 USD`. Две попытки без возврата неизвестных расходов: 0.0368448 USD. Цены через OpenRouter здесь не проверялись и платно не измерялись.

**Не реализованы:** короткий system prompt, компактная схема ответа A и её полноценный validator, соответствие девяти тем 13 этапам, durable ledger с блокировкой/атомарной записью, бюджет сайта между запусками, запрет конфигурации выше 0.50 USD, резервирование до отправки и compact send orchestration. Нет тестов восстановления бюджета и неизвестных расходов именно нового пути. Старый in-memory Budget не выполняет эти требования. Лимиты 0.05/0.50 USD нельзя считать обеспеченными для старого analyze; новый offline путь его не вызывает.

Screening намеренно строгий: общие юридические/медицинские слова primary могут блокировать даже синтетический пакет. Политика разрешения таких случаев и безопасная редактура с сохранением grounding пока не реализованы. Подтверждение SHA не снимает блокировку.

Реальный сайт может не поместиться в 40 КБ: результатом будет review_required без скрытого удаления важных фактов. Качество чтения dictionary-представления моделью и качество AI-аудита не оценивались. Registry через новый CLI не подключён; время оценки задаётся явно. Автоматического GO и клиентского заключения нет.
