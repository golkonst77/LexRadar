Дата: 2026-10-15. **Платные запросы в задании №39 не выполнялись.**
Изучены отчёт №38, его approval и dry-run, конфигурация, профиль, transport,
screening/approval pipeline и реализация постоянного бюджета.

## Причина сетевого препятствия

Внутри текущего окружения повторена только DNS-проверка:
`python3 -c 'import socket; print(socket.getaddrinfo("openrouter.ai",443))'`.
Получен `socket.gaierror: [Errno -3] Temporary failure in name resolution`.
Это происходит до HTTP, TLS, проверки ключа или платной генерации.

У сессии Codex явно задан restricted network; разрешения на выход за sandbox
недоступны (approval policy never). Поэтому запуск «обычного Python» через
инструмент Codex всё равно остаётся внутри ограниченного окружения.
Успешный ранее запуск Python непосредственно пользователем на сервере,
сообщённый в задании, согласуется с тем, что препятствие связано с сетевой
изоляцией Codex. Это наиболее вероятное объяснение, но не доказательство
конкретного механизма DNS-блокировки: одновременный контрольный запуск вне
Codex в рамках задания недоступен; временный сбой DNS сервера не исключён.

Отдельный web-инструмент смог прочитать публичные
[metadata OpenRouter](https://openrouter.ai/api/v1/models/deepseek/deepseek-v3.2/endpoints).
Он использует другой сетевой контекст, поэтому этот результат не доказывает
доступность из Python sandbox или непосредственно с сервера. Наблюдались
нужные model_id/tag, status=0 и цены $0.259/M и $0.80/M.
Скрипт не доверяет этому наблюдению вместо собственной свежей проверки.
Системный DNS, сеть, firewall и конфигурация сервера не менялись; обходы
ограничений, альтернативные IP/DNS и proxy overrides не применялись.

## Подготовленный скрипт

`scripts/run_paid_pilot_039.py` имеет executable bit. Пути привязаны к корню
репозитория, поэтому не зависят от текущего каталога процесса.

По умолчанию выполняется исключительно локальный dry-run с запретом socket
connect/create_connection и transport POST. Ключ не читается. Временные
результаты удаляются. Для платного режима требуется явный `--execute`.

Платный режим:

1. Берёт неблокирующую эксклюзивную flock-блокировку `work/first-pilot/run-039.lock`.
2. Проверяет integrity и цитаты, SHA256
   `7b15886086ccf838a14a9a974ebee722f732fa7629478e14289a745392292acd`,
   существующий `work/first-pilot/approval-038.json` штатной проверкой approval,
   screening и профиль штатным pipeline. Approval не создаётся и не редактируется.
3. Использует строго прежний `work/first-pilot/site-ledger.json`.
   Наличие любой предыдущей записи clinic.example, даже known с нулевой
   стоимостью, блокирует новую попытку. Pending/unknown также блокируются.
   Путь не заменяется, история не очищается. «Неизменный ledger» означает
   тот же постоянный ledger с сохранённой историей; штатные reserve/settle
   должны записать в него новую попытку при разрешённом выполнении.
4. Проводит dry-run, затем читает существующий ключ только из
   `/home/golkonst/.config/lexradar/openrouter.key`. Не печатает и не сохраняет
   ключ, ответы account GET или тела сетевых ошибок.
5. Однократно получает свежие endpoints metadata, `/key` и `/credits`.
   Проверяет ровно deepseek/deepseek-v3.2 и siliconflow/fp8, status=0,
   необходимые параметры, контекст и output limit, цены не выше профиля,
   платный ключ, остаток ограниченного ключа и баланс аккаунта не ниже резерва.
   Схема key сверена с [официальной документацией](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key).
   Неизвестные/нечисловые/нефинитные финансовые значения приводят к остановке.
6. Повторяет локальные проверки и dry-run после GET. Срок профиля сохранён:
   после **2026-10-16 12:00 UTC** — остановка, без автоматического продления.
7. Штатный pipeline резервирует бюджет. Непосредственно перед POST transport
   повторно проверяет модель, only, запрет fallbacks, цены, reasoning и формат;
   создаёт `work/first-pilot/attempt-039.json` через O_EXCL с fsync файла и
   каталога. Только после этого разрешён один вызов штатного transport.

Повторный запуск блокируется маркером и/или ledger. Маркер не удаляется даже
при HTTP-ошибке, timeout, исключении, невалидном ответе или успешном ответе.
Если процесс погибнет после резервирования, pending в ledger сохраняется.
Если timeout обработан pipeline, расход остаётся unknown с сохранением
резерва. Автоматических повторов нет. Не удалять маркер/ledger/записи ради
повторной попытки: при неопределённом исходе нужна ручная сверка OpenRouter
Activity и расходов, а не новый запрос.

Настройки: один auditor, retries=0, output=2000, максимум бюджета $0.05,
only=[siliconflow/fp8], allow_fallbacks=false, require_parameters=true,
max_price, reasoning.enabled=false, JSON object. Резерв $0.009756687.
Лимиты локального бюджета и max_price не являются независимым контролем
биллинга провайдера; неизвестный расход или overrun блокируют продолжение.
Результаты платного запуска будут в приватном `work/first-pilot/run-039-*/`.
HOLD / not_confirmed / client_release_allowed=false сохраняются.
