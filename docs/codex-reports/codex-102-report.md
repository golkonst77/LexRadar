## Инвентаризация и подтверждённые причины

Прочитаны collection.json/артефакты/журналы runs-099, пакет/выборка/хеши runs-100,
все девять исходных находок и cookie review из

requests.jsonl, summary.json и review/CHATGPT-REVIEW.md. Capture №101 сообщает
redacted=false: исходный текст ответа не редактировался механизмом секретов.

Сбор №99: 37 страниц HTTP 200, 36 полных наборов, 1 частичный на странице отзывов,
документов 0. Пакет №100: четыре юридически значимые страницы, **198730 байт**,
SHA-256 `db4af395dee973704e3ade8cc7691b382c7ca23e5502754c57b677ee36fa7205`.
Все четыре текста воспроизводятся из сохранённых HTML. Результат №101:
37866 входных / 10164 выходных токенов, **$0.0297945**, 107.17 секунды всего
(107.08 — длительность запроса в ledger). Эти показатели исторические.

Общие причины старого HOLD:

1. Во всех девяти находках AI **не вернул legal_position**. Схема совместимо
   подставила undetermined. Старый фильтр требовал possible_issue; угадывать
   юридическую позицию из русского текста было бы небезопасно.
2. Validator сравнивал каждую цитату с одним source всей находки. Это отбрасывало
   правильные цитаты с других страниц, хотя evidence_id указывал реальный источник.
3. Для полного fact_supported требовалось, чтобы *каждый* перечисленный
   evidence_id содержал цитату, равную всему fact. Перечисление четырёх страниц
   с повторяющимся баннером и несколько различных подтверждающих цитат приводили
   к ложному отрицанию факта.
4. Одна ошибочная цитата сбрасывала valid_spans всей находки. Не было отдельного
   перечня подтверждённых фрагментов/ошибок привязки/ошибок текста.
5. В ответе AI действительно есть неточные кавычки, многоточия, опечатки и
   пересказы вместо требуемого fact-цитирования. Их нельзя исправлять незаметно.
6. Положительные декларации сайта, подтверждённый риск и доказанное нарушение
   не имели самостоятельного пути к документированной оценке услуги.

## Изменения

### Доказательства и совместимость

`auditors/grounding.py`: quote_locations возвращает все дословные вхождения в
доступных воспроизведённых текстах, включая повторяющийся баннер. check_quote
возвращает MATCH / WRONG_SOURCE / NOT_FOUND / BAD_OFFSETS с реальными URL.
Разные URL одной находки больше не смешиваются. Старая exact_locations сохраняет
контракт единственного span для её вызывающих функций.

`auditors/validator.py`: каждая цитата проверяется отдельно, валидные смещения
добавляются лишь при однозначном нахождении. fact_supported по-прежнему требует
дословного подтверждения всего fact, а не пересказа. Другие неверные цитаты не
стирают подтверждение отдельного факта; они фиксируются самостоятельно. Проверки
неизвестных/дублирующихся evidence_id, наличия источников, reading/provenance,
размеров схемы и cookie-review сохранены. Неизвестные ссылки остаются ошибкой
структуры, а не молча исправляемым доказательством.

`finding_assessment.py`: новый sidecar schema_version=102 с тремя осями, четырьмя
фактическими состояниями и пятью классами. Старые AI/AnalysisReport-схемы не
менялись. AI не может вписать локальное коммерческое согласование в свой ответ.
Коммерческий обзор привязан к packet_sha256 + analysis_sha256; проверяет индексы
действительно совпавших цитат, фактический объём, конкретную потребность, услуги,
результат работ, имя/время проверившего. Контрцитата не равна автоматически
контрдоказательству: её смысл явно подтверждает независимый проверяющий.

Старые интерфейсы оставлены с прежним консервативным предварительным отбором.
Новый операторский маршрут не объявляет GO по одной AI-гипотезе. В существующий
`evidence_review.py` добавлены независимые фактические состояния/результаты цитат,
чтобы старые отчёты тоже показывали не только прежний бинарный вывод.

Промпт `single-a-v3-cookie` дополнен явным требованием legal_position и точного
fact; cookie_analytics_review остаётся обязательным. Версия сохранена, хеш
промпта изменился. Старый capture №101 не пересоздаётся из нового промпта.
Старый скрипт №101 с жёстко закреплённым старым prompt hash безопасно остановится;
для новых запусков используйте операторский CLI.

### Сбор и cookie

`collector/runner.py`: повторные URL навигации удаляются до лимита ссылок, чтобы
несколько одинаковых меню не вытеснили PDF/юридические источники. Синтетический
тест с 250 повторными ссылками подтверждает обнаружение consent.pdf. Это
подтверждённый недостаток алгоритма, но не обещание, что все пропущенные PDF
сайта №99 теперь обязательно скачиваются: свежий сетевой сбор не выполнялся.
SSRF, TLS, robots, same-origin и бюджеты обхода не ослаблялись.

`cookie_inspection.py`: опциональный --cookie-check инспектирует сохранённый HTML
для Метрики, GA, GTM, других известных интеграций, cookie-фрагментов, возможных
кнопок согласия/отказа/настроек с точными источниками. Для загрузки скриптов,
первичных cookies и реакции на отказ сохраняется NOT_VERIFIED.

**Живой динамический cookie-аудит не реализован и не выдаётся за выполненный.**
Существующий браузер специально отключает JavaScript/подзапросы; Fetcher защищает
свои HTTP-запросы, а не произвольные сетевые каналы исполняемого браузерного JS.
Простое включение скриптов ослабило бы SSRF-защиту. Отдельный безопасный live worker
с принудительной сетевой изоляцией остаётся существенным ограничением версии.
В текущем Codex сеть/Chromium также блокируются sandbox; ограничения не обходились.

### CLI, диагностика, отчёты и КП

Добавлены `operator_audit.py`, `audit_progress.py`, диспетчер `lexradar audit` и
стандартный `python -m lexradar`. По умолчанию — только сбор/подготовка. Есть
--dossier, --saved-audit, --cookie-check, --static-only, --commercial-review.
Все output должны быть новыми; исходные досье и аудиты хешируются, symlink-пути
отклоняются. Целые юридические страницы выбираются под лимит 200000 байт, пропуски
объявляются; тексты не переписываются и не обрезаются.

Платный путь требует --paid, --allow-external-transfer, ключ в окружении,
просмотр точного пакета и интерактивную фразу с SHA/бюджетом. --mvp-no-screening
требует дополнительного явного подтверждения и отключает только скрининг ПДн.
Single A, GPT-5 Mini, max_tokens 28000, reasoning low, retries 0, timeout 120,
fallback запрещён, бюджет $0.50. Серверный ключ в этом задании не читался.

Orchestrator принимает необязательный progress callback; существующие вызовы
работают без него. Терминал/events.jsonl содержат этапы, время, размер, модель,
промпт, отправку, heartbeat каждые 10 секунд, usage/стоимость, валидацию,
коммерческий отбор и итог. Heartbeat — отдельное ожидание Event, не повтор запроса.
Сетевые исключения журналируются безопасными типами/кодами без traceback/секретов.
Расход при неизвестном результате не считается нулевым: резерв сохраняется,
возможное списание явно отмечается. Отказ модели отдельно распознаётся.

Provider новых запусков сохраняет полный HTTP JSON envelope без заголовков и
исходный model content до валидации, с защитой секретов. Историческую HTTP-обёртку
№101, которой раньше не сохранялось, задним числом не выдумываем.

При HOLD — содержательные report.md/report.html, assessment.json, summary.json и
шаблон коммерческого обзора. При GO — proposal.html из утверждённого v2.4,
только четыре разрешённых поля персонализации, цитаты из MATCH, конкретные
работы проверяющего; риск явно отделён от нарушения. Рассылки/автовыпуска нет.
Проверка GO с КП выполнена только на синтетических данных, не подогнана под клинику.

6. Положительный факт не продаётся как дефект.
7. Неподтверждённые гипотезы не допускаются без точных доказательств.
8. GO с хеш-привязанным обзором и конкретной работой, неизменный шаблон.
9. HOLD без достаточной аргументации, контрдоказательство, испорченные хеши.
10. Отказ/ошибка/timeout-подобная ошибка не повторяется, стоимость неизвестна.

12. Нет бюджета — request_sent=false.
13. Браузер недоступен — понятный HOLD, без скрытого fallback/ослабления защиты.
14. Heartbeat пассивен, пишет журнал и прекращается вместе с ожиданием.

В старых тестах актуализированы подтверждённо устаревшие ожидания GPT-5 Mini,
