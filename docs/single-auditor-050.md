# LexRadar Single Auditor MVP №50

Отдельный маршрут, прежние сборщик, досье и двухаудиторный №48 сохранены:

```bash
python -m lexradar.single_auditor /path/to/dossier /path/to/recorded-A.json /tmp/new-run --pdf
```

Вход — один JSON `AIAuditorResult` с `auditor=A`, без обёртки A/B.
Команда работает только офлайн и не читает ключ API. Qwen не настраивается
как обязательный аудитор, не вызывается и не участвует в GO.

В находках добавлено необязательное поле `proposed_work`:
`legal_documents`, `webmaster_instructions` или пустой список. Старые ответы
совместимы, но без подходящей работы находка не становится коммерческой основой.
Объём работы и условия применимости описываются в `additional_checks` и
`legal_interpretation`; норма — в `normative_basis`.

GO требует одной существенной находки `potential/possible_issue`, подходящей
нашим услугам, с положительным фактом и точной цитатой во всех указанных
источниках, полным качеством использованного доказательства и воспроизводимым
оригиналом. Неполное покрытие других тем само по себе не запрещает GO.
Гипотезы, отрицательные утверждения и недоступные доказательства не дают GO.
Проверка всех хешей досье остаётся обязательной; повреждение останавливает запуск.

`observations.fact_status=established_excerpt` означает установленное наличие
цитаты в локальном оригинале, а не доказанность её юридической интерпретации.
`unconfirmed_assumption` не является коммерческой основой;
`legal_status=potential_violation` остаётся гипотезой о праве. Проверка цитаты
не способна доказать применимость нормы или фактическое поведение сервера сайта.

При HOLD генератор КП не вызывается и `client/` отсутствует. При GO используется
прежний ограниченный fake генератор с проверкой структуры, ID, хешей и экспортом
HTML/PDF. Свободные утверждения, новые нормы, цены и сроки в КП не разрешены.
Это локальный синтетический проект предложения. Сохраняются
`legal_production_status=HOLD`, `send_allowed=false`, `release_allowed=false`.
`bind_review`/`review_matches` привязывают просмотр к байтам документов, но не
аутентифицируют согласующего. Для выпуска нужна отдельная доверенная процедура
человеческого согласования; механизма отправки в маршруте нет.

## Подготовленный реальный адаптер

`single_auditor.DeepSeekAdapter` использует существующий `OpenRouterProvider`
и транспорт без fallback, с проверкой модели ответа и ошибок провайдера.
Он запрещён в offline оркестраторе. Профиль явно фиксирует:

- модель `deepseek/deepseek-v3.2`;
- бюджет $0.50, резервирование перед каждой платной попыткой;
- потолок цены: $1 / миллион входных и $2 / миллион выходных токенов;
- 4000 выходных токенов, консервативная граница входа 240000 UTF-8 байтов
  с overhead 1024 как верхняя оценка токенов; пакет до 200000 байтов;
- 45 секунд на HTTP-попытку, один повтор, backoff до 1 секунды
  (не более двух попыток и 91 секунды сетевого ожидания с backoff);
- ответ до 500000 байтов; ошибки неизвестной стоимости сохраняют полный резерв.

Это защитные потолки, а не проверенные текущие цены или доступность модели.
Реальная стоимость сверх резерва останавливает дальнейшие попытки; внешний
провайдер не даёт гарантии абсолютного финансового потолка.

Первый реальный запуск выполняется отдельно после разрешения передачи точного
пакета и бюджета, через существующий `analyze` с `profile()`,
`message_builder=single_auditor.messages_for`, `provider=DeepSeekAdapter()`,
`mode='openrouter'`, `allow_external_transfer=True` и `packet_approval`.
Без разрешения и approval запуск блокируется. CLI №50 не имеет платного флага.
После inference нужно повторно применить `single_auditor.commercial` к свежему
`load_packet`, проверить факты, актуальность/применимость норм и объём услуги
человеком. Только затем готовить и согласовывать точные клиентские документы.
В задании №50 реальные вызовы не выполнялись.

## HTTP-транспорт после задания №52

Транспорт читает ответ ограниченными порциями, ограничивает размер и обновляет
socket timeout по оставшемуся времени. Ненулевой остаток `Content-Length` после
чтения — `ProviderError('transport_error', retryable=True)`. Обрыв внутри chunk
или до завершающего нулевого chunk также отклоняется через `IncompleteRead`.
У `HTTPResponse.read1()` нет автоматической проверки полного Content-Length:
после раннего EOF поток закрыт, но `length` остаётся положительным. Поэтому
проверка остатка выполняется явно после цикла.

Контракт `ProviderError.diagnostics` обратно совместим: по умолчанию `{}`;
транспортные ошибки содержат только `phase` (`open`/`read`), `kind`
(`timeout`, `deadline`, `incomplete_read`, `http_protocol`, `network`),
`http_status` (число или null) и `received_bytes` (число уже накопленных байтов
тела без HTTP framing). Deadline сохраняет код `transport_timeout`, остальные
сетевые/протокольные ошибки — `transport_error`. Превышение размера сохраняет
`response_size_exceeded`. Тексты исключений, тело, заголовки, ключ и запрос
в diagnostics не записываются. Исходное исключение сохраняется как cause;
его traceback нельзя публиковать как безопасную диагностику.

Границы стандартной библиотеки: EOF завершает ответ без Content-Length/chunked,
поэтому отличить его от обрыва невозможно. После нулевого chunk Python допускает
EOF без пустой строки, завершающей trailers; это не строгий валидатор HTTP framing.
Отсутствие самого нулевого chunk и неполные данные chunk отклоняются.
`read1()` для chunked может выполнить несколько чтений framing; socket timeout
ограничивает блокирующие операции, но не гарантирует жёсткий общий wall-clock
deadline при медленной передаче framing. Транспорт использует внутренний путь
`response.fp.raw._sock`; совместимость проверена локально на Python 3.13.5,
произвольные HTTPResponse-обёртки этим контрактом не поддерживаются.

## Явный тестовый режим MVP_NO_SCREENING (№55)

Отдельный реальный CLI: `python -m lexradar.single_auditor_live dossier output
--packet-approval approval.json --allow-external-transfer --mvp-no-screening`.
Последний флаг отключает только блокировку по screening персональных данных;
без него действует прежний screening. В Python это `analyze(...,
mvp_no_screening=True)` с неизменёнными `profile()` и `messages_for` Single A.
Режим и предупреждение «проверка передачи персональных данных отключена»
записываются в локальные отчёты. Подтверждение SHA256 конкретного пакета,
разрешение OpenRouter, целостность, размеры и бюджет остаются обязательными.
Команда не отправляет результаты клиентам. Точная команда для досье №54,
результаты офлайн-проверки и условия запуска — в
[`codex-055-report.md`](codex-reports/codex-055-report.md).
