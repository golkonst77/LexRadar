# Независимая офлайн-сверка PR #14

```bash
lexradar primary-audit examples/primary-audit/dossier --sector medical \
  --as-of 2026-10-10T00:00:00Z --output work/primary
lexradar verify-primary examples/primary-audit/dossier \
  --primary work/primary/audit.json \
  --assessment work/primary/internal-assessment.json \
  --registry examples/legal-sources/registry.json --output work/verification
```

Оба каталога результата должны быть новыми. Исходное досье не изменяется;
15 экспортов первичного этапа сохраняются, четыре отчёта проверки пишутся отдельно:
`independent-verification.json`, `verified-legal-findings.json`,
`verified-commercial-work.json`, `verification-gaps.json`.
Примеры относятся только к синтетическим материалам. Приватный пилот не опубликован.

`LocalResearch` завершает Stage I по досье и реестру до сопоставления Stage II.
Он не получает находок, выводов A/B, коммерческих кандидатов или их confidence.
Сектор и дата оценки передаются как заявленные параметры исследования, а не как
доказательство реальной даты публикации или медицинского статуса организации.
Используются существующие консервативные парсеры и повторный `audit_saved_dossier`.
Это независимость входных выводов, а не второй независимый юридический эксперт:
общий алгоритм способен повторить собственные пропуски.

Проверяются безопасные локальные пути, наличие файлов, размер, SHA-256 реальных
байтов, воспроизводимость производного текста, координаты в исходном HTML,
принадлежность диапазона повторно извлечённой области и цитата внутри этой области.
Описания фактов и их объектные связи сопоставляются с повторным извлечением;
произвольный импортированный текст не становится подтверждённым фактом.
Хеш JSON и совпадение двух отчётов не аутентифицируют источник. В конце повторяется
проверка досье; изменение во время обработки останавливает выпуск результата.
При недостоверном досье импортированные утверждения остаются `insufficient_evidence`.
Ошибка реестра не уничтожает доступные технические наблюдения, но блокирует нормы.

Статусы относятся к техническим фактам: `verified_fact`, `partially_verified`,
`contradicted`, `insufficient_evidence`, `requires_external_check`. Последний
предусмотрен контрактом; недоступная внешняя проверка не симулируется. Полнота
HTML ограничена статическими диапазонами; повреждённый суффикс и границы восстановления
показаны отдельно, знаменатель всех частей повреждённого HTML неизвестен.
PDF повторно извлекается существующим ограниченным процессом: известное общее
число страниц, реально доступные текстовые страницы, пропущенные номера, усечение,
причины и необходимость визуальной проверки. Скан не означает пустой/отсутствующий
документ. Изображения и макет, OCR и фактическая работа формы не исследуются.

Для точного названия организации собирается соседний текст из повторно прочитанной
области. Маркеры обучения/биографии/партнёрства — контекстные кандидаты, а не
окончательное определение роли. Идентичность и оператор остаются неподтверждёнными;
данные организаций не объединяются. Отсутствие checkbox, ссылка Medflex,
GTM или отсутствие номера закона не устанавливают нарушение и передачу данных.

Нормативные кандидаты выбираются по области вопроса из существующего реестра.
Его проверки включают локальный оригинал карточки, цитату, идентификатор, пункт,
заявленную редакцию и интервалы. Подбор по области **не доказывает применимость**.
Аутентифицированного происхождения и актуальной редакции в MVP нет: всегда
`normative_review_required` / `unestablished`, без санкций и юридического подтверждения.
В приложенных примерах нормативные тексты являются синтетическими шаблонами.

Повторное исследование включает все сохранённые материалы, а не только исходные
вопросы. `new_findings` показывает вопросы с ранее не представленными фактами,
`new_observations` — дополнительные наблюдения со своей проверкой цитат, включая
формы, документы и ресурсы, которые не превращаются в юридический вопрос.
Уже одинаково пропущенные общим парсером элементы таким сравнением не обнаружатся.
Семантическая оценка противоречий между документами и формами, достаточности нормы
и контекста вне сохранённого досье остаётся действием для независимого эксперта.

Необходимость платной услуги не наследуется. Проверяется воспроизведение типа
кандидата, точного набора связанных вопросов и фактов. Даже при успешной технической
сверке новый документ нужен `unknown`, обязанность `unverified`, полный актуальный
документ `not_established`. Допускается только условная внутренняя проверка;
подготовку/замену документа нельзя рекомендовать как доказанную необходимость.
Письменное ТЗ условно зависит от установленной юридической работы. Сначала требуется
прочитать доступные документы; отсутствие внутренних материалов не блокирует
саму техническую сверку.

Все результаты: внутренние, `HOLD`, `not_confirmed`, без GO, клиентского допуска,
отправки и завершённости юридического исследования. Импорт отчёта в production
Gateway не создаёт доверия. Клиентских писем, КП, живых запросов, LLM и новых
зависимостей этот этап не добавляет. `gap_count` — число уникальных действий и
ограничений проверки, а не число нарушений; `technical_fact_count` — уникальные
факты с проверенными цитатами, включая частично обследованные исходные области.
