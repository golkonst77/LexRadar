# Independent AI Auditors v0.3

Слой анализа принимает сохранённое досье Collector v0.2. Он не создаёт
GatewayDecision, не вызывает Gateway, не отправляет клиентам сообщения и не
устанавливает доказанность юридического нарушения.

## Архитектура

`evidence.py` проверяет JSON, статусы, ссылки, файлы, SHA-256 и ограничения PNG;
создаёт ограниченный текстовый пакет с идентичным SHA-256 для A и B.
`prompts.py` загружает разные инструкции `a-v1` и `b-v1` из Prompt Registry.
`provider.py` содержит только адаптер OpenRouter и локальный offline-демонстратор.
`orchestrator.py` выполняет отдельные запросы, разделяя только бюджет.
`validator.py` проверяет схему, coverage и evidence ID, снимает неподтверждённые
заявления модели о проверке права и доказанности. `disagreements.py` сопоставляет
структурированные утверждения, направляя все результаты на независимую проверку.

Каждый запрос имеет ровно два новых сообщения: system и user. User-пакет A и B
идентичен; инструкции различны. История чата, ответ A и промежуточные ответы не
передаются B. Повтор после транспортной ошибки использует тот же свежий контекст,
без предыдущего ответа. Последовательное выполнение не означает общий контекст.
В журнале сохранены хеш пакета и версия/хеш фактического промпта каждого запроса.

## Запуск без сети и без API-ключа

```bash
lexradar analyze work/audit --output work/analysis
```

По умолчанию `--mode offline`: никакой LLM не вызывается. Это проверка конвейера
с пустыми находками и девятью направлениями `insufficient_evidence`, а не
имитация реального юридического аудита. Для воспроизводимого демонстрационного
запуска можно использовать `examples/analysis-dossier`; он содержит только синтетику.
Каталог результата должен быть новым; существующее досье не перезаписывается.

## Настройка OpenRouter

1. Скопируйте `examples/openrouter-config.json` и замените оба placeholder ID
   актуальными **конкретными идентификаторами OpenRouter**, выбранными вами.
   Можно задать одну модель, но отчёт явно укажет ограниченную независимость.
2. Укажите цены-ограничения в USD за миллион токенов отдельно для prompt и completion,
   предел output tokens, общий `max_budget_usd`, таймаут и число повторов.
   Проверьте соответствие выбранной модели JSON-режиму и обязательным параметрам API.
3. Задайте ключ только в окружении процесса `OPENROUTER_API_KEY` через безопасный
   механизм вашей среды. Ключ не задаётся в JSON-конфигурации, аргументах CLI или файлах проекта.
4. Подготовьте локальный preflight (без ключа и сети):

```bash
lexradar preflight work/audit --output work/review
```

Человек должен просмотреть **весь `work/review/packet.json`**, фактический состав
передаваемых данных и `preflight.json`. SHA-256 относится к точным UTF-8 байтам
user-пакета, одинакового для A/B. `approval.json` создаётся неподтверждённым.
После проверки заполните `reviewer`, `approved_at` (ISO-8601 с часовым поясом),
`contents_reviewed: true`, `approved: true`, сохранив указанный `packet_sha256`.
Это явная запись человеческого решения; CLI не подтверждает пакет автоматически.
Если есть подозрения, отправка блокируется даже при подтверждении. Исправьте
состав досье локально, сохранив согласованность артефактов/хешей, затем создайте
новый preflight и получите новое подтверждение. Автоматического удаления ПДн нет.

Поиск консервативно проверяет строки всего исходящего пакета (тексты, URL,
формы, реквизиты, метаданные) на email, телефоны/идентификаторы, имена, даты и
признаки медицинских/идентификационных сведений; нормализует Unicode, невидимые
символы и URL-кодирование. В диагностике только категории/местоположения.
**Эвристики не гарантируют отсутствие ПДн**; возможны пропуски и ложные срабатывания,
включая общие медицинские термины и публичные контакты. При сомнениях передача
останавливается. Подтверждение не является способом обойти обнаруженные признаки.
Локальные preflight-файлы также требуют защиты доступа и не должны попадать в Git.

5. Явно разрешите передачу утверждённого пакета внешнему провайдеру:

```bash
lexradar analyze work/audit --output work/analysis \
  --mode openrouter --config work/openrouter-config.json --allow-external-transfer \
  --packet-approval work/review/approval.json
```

Без конфигурации, флага согласия, подтверждения точного SHA-256 или ключа запрос
не выполняется. Общего флага недостаточно. Перед каждым вызовом повторяются
скрининг и проверка подтверждения. Изменение исходящего пакета после утверждения
блокирует запуск; в ходе запуска используется неизменяемый снимок текста.
`run.json` сохраняет запись подтверждения. Шаблон — не электронная подпись:
аутентификация личности проверяющего и защита локальной записи вне MVP.
В ходе разработки и CI реальных или платных запросов нет. Разрешение относится
к явному запуску CLI; оно не включено по умолчанию и не наследуется от offline-запуска.
Адаптер использует фиксированный HTTPS endpoint OpenRouter, доверие TLS и
настройки proxy среды; HTTP-перенаправления запрещены, другой API не используется.
Fallback модели/провайдера выключен; неожиданный model ID в ответе отклоняется.
`openrouter/auto` и алиасы, меняющие возвращаемый ID, не подходят для этой строгой проверки.

## Бюджет и журнал

Перед **каждой** попыткой резервируется верхняя оценка затрат по размеру UTF-8
контекста плюс запас на framing и максимальному числу output tokens. Ценовые
ограничения передаются в `provider.max_price`, `require_parameters=true` и
`allow_fallbacks=false`. Бюджет общий для A, B и повторов. Если резерв не помещается,
новый запрос не отправляется и фиксируется `budget_exceeded` с `request_sent=false`.

При наличии `usage.cost` учитывается фактическая стоимость и освобождается
неиспользованная часть резерва. Если стоимость неизвестна или запрос завершился
ошибкой, полный резерв остаётся списанным консервативно. Токены учитываются,
если OpenRouter их вернул. Если фактический charge неожиданно превышает резерв,
он честно отражается в отчёте и дальнейшие запросы блокируются.

Это контроль расходов по заявленным API-ограничениям, а не гарантия счёта третьей
стороны: ошибка тарификации, скрытая доплата или нарушение provider caps могут
дать charge выше оценки уже после запроса. Для жёсткого финансового потолка
нужен дополнительный лимит ключа/счёта в OpenRouter, который этот MVP не меняет.

Повторяются только временные транспортные ошибки, HTTP 429 и определённые 5xx;
число повторов и задержка ограничены. 401, redirects, некорректный JSON и битые
ссылки не приводят к бесконечным повторам или автоматической смене модели.

Результаты: `analysis.json`, `requests.jsonl`, `run.json`. В журнале только модель,
время, версия/хеш промпта, хеш пакета, попытка, факт отправки, статус, usage и charge.
Ключ, сырые запросы/ответы и provider error bodies не записываются. Сам отчёт
содержит нормализованные находки; сырые ответы LLM не сохраняются. Досье/выводы
могут содержать публичные данные: перед реальной передачей проверяйте их состав.

## Доказательства и ограничения чтения

До LLM проверяются схема, уникальность ID, ссылки страниц/документов, наличие и
целостность файлов, происхождение и notice скриншотов. Symlink и выход за каталог
запрещены. Текст страницы должен совпадать с хешированным текстовым артефактом;
если такого файла нет при partial-сборе, текст не передаётся как проверенный.
Слишком большой пакет отклоняется без молчаливого усечения; уменьшите сбор.

Передаётся только извлечённый текст и метаданные (включая формы/реквизиты).
**Байты HTML, PDF и пиксели PNG не передаются.** Модель не читает изображения.
Scan/no-text PDF получает `unverifiable` для основанных на его содержимом находок,
с необходимостью визуальной проверки. Для смешанного PDF находка допустима
только об имеющемся фрагменте: `examination_scope: "text_excerpt"`,
`fact_assertion: "present"`, `text_grounding` с `evidence_id` и `exact_quote`.
Наблюдаемый `fact` должен буквально совпадать с цитатой доступного текста каждого
смешанного документа, на который ссылается находка. Без такой привязки, при
`whole_document`/`unknown` или утверждении отсутствия сведений — `unverifiable`,
`fact_assertion: "unknown"`; первоначальный текст утверждения, правовые основания
и ограничения сохраняются. Даже найденная цитата подтверждает только вхождение
текста: её значение и юридическая интерпретация требуют человеческой проверки.
Непрочитанные страницы всегда явно исключены из проверки. Частичный сбор никогда не выдаётся за полное обследование.
Целостность файлов не доказывает актуальность содержимого или юридическую истинность.
PDF-текст взят из Collector; повторное извлечение/семантическая сверка PDF в v0.3 отсутствует.

Материалы сайта отделены как `untrusted_collector_data`; промпты запрещают
исполнение вложенных инструкций. API не получает tools, и ответы не исполняются
как команды. Эти меры и схемы ограничивают последствия prompt injection, но
не гарантируют, что LLM никогда не исказит анализ под влиянием текста сайта.
Нормализованные факты и юридические гипотезы всё равно требуют независимой проверки.

## Находки и сравнение

AIFinding хранит проверяемое утверждение, URL/evidence IDs, интерпретацию, статью/
пункт и требование НПА, confidence, materiality, альтернативы, ограничения и
дополнительные проверки. Согласие или высокая уверенность не подтверждают нарушение.
Все правовые ссылки имеют `actuality_status=unverified`, `verified_source=null`.
LLM URL хранится только как `claimed_source`; независимая проверка законодательства
в v0.3 не реализована. Любой ответ `confirmed` понижается до `potential`;
недоступность/непереданный текст переводят находку в `unverifiable`.

Сравнение использует topic, subject, claim_code, пересечение evidence IDs,
структурированное present/absent/unknown, legal_position, идентификатор НПА/пункт
и существенность. Текстовое равенство не требуется. Различаются полное и частичное
структурированное согласие, противоположные фактические утверждения, юридические
расхождения, находка только одного аудитора и недостаточная доказательность.
Все категории имеют `requires_review=true`; full_agreement не означает юридическую
правильность. Несовпадающие claim_code и неоднозначные группы требуют ручного
семантического сопоставления: детерминированный comparator не понимает все парафразы.

Новые AIAuditorResult/AnalysisReport намеренно отделены от подтверждённых контрактов
v0.1. `automatic_go_allowed=false`, `automatic_send_allowed=false`, требуется
независимая юридическая проверка. CLI/модели v0.1 и Collector v0.2 сохраняются.
Нет интеграции с Gateway или этапом v0.4.
