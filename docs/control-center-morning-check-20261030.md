## Что проверено

Итог: **60 тестов unittest**, включая подслучаи внутри тестов.
Исходный набор до новых тестов: 55, успешно. Добавлено пять тестовых методов;

HTTP проходит через настоящий `ControlHandler` и HTTP-парсер стандартной
библиотеки с in-memory соединением, не через подмену `do_POST`.
Номер 8080 в тестовом объекте сервера проверяет Host, но не открывает этот порт.

- POST `/collect/preview`: совпадающие Host/Origin для `127.0.0.1:8080`
  и `localhost:8080` дают 200 и HTML предпросмотра. Проверены регистр имени
  и схемы, нормализация порта, стандартный HTTP-порт и отсутствие Origin.
- `Origin: null`, чужая схема/домен/порт, подмена localhost на 127.0.0.1,
  userinfo, path/query/fragment, неверный порт, управляющие символы,

  остаётся ограничен localhost/127.0.0.1; разрешения произвольных доменов нет.
- Отсутствующий/ошибочный CSRF и отсутствующий/неверный confirm отвергаются
  как при совпадающем Origin, так и без него. Ограничения тела и запрет
  chunked сохраняются. Диагностика отказа POST не содержит тело/секреты.
- Заголовок ответа `Referrer-Policy: same-origin` проверен. Отсутствие Origin
  допускается по прежней политике только с CSRF и отдельным подтверждением.
- UI `/jobs` содержит выбор отрасли и форму preview. Для N=1: preview не
  создаёт каталог запуска; отдельный POST подтверждения создаёт одно задание,
  возвращает 303 на карточку; наблюдаются queued → running → succeeded.
- Во время running виден журнал stub и `Refresh: 5`; после завершения
  автообновление прекращается. Проверены summary, сохранённый файл БД stub,

- Два задания выполняются последовательно; ожидающее не начинает работу
  до окончания первого. Два одновременных подтверждения одного preview
  создают ровно одно задание. Повторное использование токена отвергается.
- Проверены пределы N, отрасль, имя, подмена параметров после preview,
  истечение токена и блокировка запуска диагностикой зависимостей.
- Exit code 7, пустой CSV, отсутствие контактов/сайта, неправильный выходной
  файл, дубликаты доменов, Unicode/IDNA-дубликаты, некорректные URL,
  булевый exported_total, частичный результат и повреждённая JSON-сводка
  не считаются успехом. Неуспешные результаты не импортируются и не скачиваются.
- Отмена ожидающего Parser через POST не создаёт каталог; отмена активного
  через POST завершает process group и дочерний stub-процесс. Неверный CSRF
  не отменяет задание. Timeout также завершает дочерние процессы. После
  отмены и timeout новое явно подтверждённое задание успешно выполняется.
- Выход CLI с оставленным ребёнком не блокирует чтение журнала. При аварийном
  исчезновении владельца supervisor завершает группу. После нового открытия
  того же временного состояния running становится failed, queued — cancelled,
  предпросмотры исчезают, автоматического повторного запуска нет.
- Второй владелец одного каталога очереди отвергается. Проверены ограничения
  журналов, маскирование ключей, безопасные пути и отказ в выдаче symlink CSV.

Stub принимает фактические аргументы `parser_run.py`: industry, target,
max-cards, max-pages, database, output. Контракт сверён чтением настоящих
`parser_run.py`, `target_collection.py`, `lead_scoring.py`, без импорта и запуска
Parser. CSV использует BOM, `;`, реальные названия колонок и экранирование
формульных значений, как экспортёр Parser. БД stub — файл-маркер, не проверка
внутренней схемы SQLite Parser. Диагностика рабочего Parser в этих сценариях
подменена; тесты не доказывают готовность Chromium.

## Найденные и исправленные дефекты

1. `urlsplit` удаляет табуляции из Host, а пустые query/fragment не видны в
   разобранных полях. Добавлен отказ до разбора. Корректные локальные Host
   продолжают работать; существующая проверка Origin не ослаблена.
2. Общий загрузчик экспортов позволял признать успех по `other.csv`, когда
   ожидаемого `parser.csv` не было. Проверка успеха теперь требует источник
   `parser.csv` для каждого импортированного лида.
3. URL сайта с нечисловым/вне диапазона портом, управляющим символом либо
   пустым доменом после нормализации считался пригодным. Общий валидатор URL
   теперь отвергает такие значения. Это также влияет на исторические ссылки:
   некорректные URL остаются текстом, без кликабельного сайта.
4. Unicode и punycode одного сайта могли засчитываться как разные сайты.
   Проверка уникальности результата нормализует IDNA.
5. Python сравнивает True и 1 как равные: `exported_total: true` проходил
   проверку N=1. Теперь нужен именно int, совпадающий с числом пригодных лидов.
6. Чрезмерно вложенная JSON-сводка вызывала необработанный RecursionError:
   поток очереди завершался, а finally мог сохранить уже установленный
   succeeded. Ошибка теперь обрабатывается как failed, очередь продолжает
   выполнять следующие задания. Это воспроизведено до исправления.

## Ограничения

Браузер не запускался. Фактическая причина прежнего `Origin: null` не
подтверждена заголовками браузера; прежняя `no-referrer` остаётся вероятной
причиной. Новый заголовок проверен на уровне ответа, не браузерного поведения.
TCP HTTP на временном порту проверить нельзя: песочница отвергает уже
`socket.socket()` с PermissionError errno=1. Обход ограничений не применялся.

Реальные MedAdvisor/Orgpage, Chromium, DISPLAY, сеть, контакты и принадлежность
сайта организации не проверялись. Пригодность здесь — формат, уникальный домен,
непустой телефон либо email и подтверждение цели сводкой Parser, не независимая
проверка юридической принадлежности или работоспособности контакта.
Изменения не пересматривают старые уже завершённые задания в постоянной БД.
CRM, платные API, почта и генерация КП не вызывались и не изменялись.
