# Анализ организаций из Control Center

Панель запускает реальный существующий `lexradar.mvp_batch.run` из
`/home/golkonst/src/LexRadar-compact/src` через Python
`/home/golkonst/src/LexRadar/.venv/bin/python`. Основной движок и Parser v3
не изменяются. `lexradar.mvp` не используется: в нём AI синтетический.
`pipeline10` как CLI требует ровно десять строк; его штатный режим
`mvp_batch.run(mode="prepare")` поддерживает один сайт и выбран для панели.

Фиксированные параметры: `mode="prepare", max_sites=1, max_ai_calls=0,
allow_site_collection=True, ignore_robots=False`. Движок собирает до 7 HTML,
2 документов, 16 запросов, 60 секунд сбора, static_only. Панель ограничивает
весь процесс 180 секундами. Нет платных вызовов, разрешений отправки или CRM.
Это предварительная проверка существующих правил 1/2/3/5. Даже при успешном
сборе отсутствие триггеров означает HOLD, а не доказанное соответствие сайта.
Имеющееся КП и постоянный блок 4 требуют ручной проверки. Полный платный
Single A/legal review остаётся отдельной процедурой движка.

## Использование

В `/organizations` доступны кнопка «Анализ» у строки и в карточке,
галочки строк, «Выбрать все на текущей странице» и «Анализировать выбранные».
Выбор сбрасывается при переходе, фильтрации или сортировке; галочка «все»
отправляет всю текущую страницу, отдельные галочки при этом не обязательны.
Кнопка строки анализирует только эту строку независимо от остальных галочек.

«Следующие N необработанных» предлагает 10/20/50/100/200 (по умолчанию 50).
Порядок: название без учёта регистра, затем стабильный ID. Выбор идёт из
всего доступного индекса, включая успешные выгрузки Parser из state-dir,
независимо от текущих фильтров и страницы. Ограничения существующего индекса
не сняты: при предупреждениях каталога сначала проверьте полноту импорта.
Исключаются домены с успешным анализом в журнале панели, известные сохранённые
primary-audit и ожидающие/выполняющиеся сайты. Неизвестные панели CLI-запуски
не обнаруживаются. Явный выбор завершённого сайта разрешает повтор с пометкой.

Предпросмотр не делает DNS-запросов, не пишет задания и не запускает процессов.
Он показывает фактические сайты, ограничения и причины пропуска. URL приводится
к корню сайта, www объединяется при дедупликации. Неоднозначные сайты и
небезопасные URL пропускаются. Предпросмотр действует 15 минут, одноразовый;
при подтверждении активные домены проверяются повторно под общей блокировкой.
Только окончательный запуск требует явного чекбокса подтверждения. POST
защищены существующими Host/Origin/CSRF проверками; отмена не требует второго
чекбокса. DNS pinning, private/link-local блокировка и проверка редиректов
выполняются штатным транспортом LexRadar, PDF генерируется offline.

Пакет и каждый сайт сохраняются в `jobs.sqlite3` существующего state-dir.
Один worker выполняет весь пакет последовательно; задания Parser панели
ожидают в той же очереди. Лимиты: 200 активных сайтов и 1000 записей журнала
(пакет также занимает запись). Другие процессы Parser не сигнализируются и
не перезапускаются. Внешние CLI-запуски не входят в очередь панели, поэтому
оператору следует избегать одновременного внешнего анализа тех же сайтов.

`/jobs` показывает прогресс X/Y и ссылки на сайты пакета. Страница сайта
содержит лог до 64 КиБ, статус, даты, переход к организации и доступные
`manifest.json` (сводка), `report.md`, `results.csv`, `review.json`, `proposal.pdf`.
Полное досье остаётся локально в `state-dir/<site-job-id>/analysis/`.
PDF создаётся штатным движком только при наличии триггеров и доступного
Chromium. Отсутствие PDF само по себе не делает успешно собранный анализ ошибкой.
«Успешно» означает проверенный пакет доказательств, не разрешение отправки КП.
Ошибка сайта не останавливает следующие. Отмена пакета останавливает его
собственную группу процессов и отменяет оставшиеся сайты. После рестарта
выполнявшиеся записи получают ошибку «прервано», ожидающие — «отменено»;
автоматического сетевого повтора нет. State-dir не удалять.

## Контакты

Проверены `mvp_batch.read_csv`, `write_prepared_proposal`, модели коллектора и
экспорт `review.json`: email используется как вход, распознавание полей формы
не является извлечением контактов организации. Выбранная точка входа не
экспортирует проверенные email/телефон с URL-источником. Поэтому панель не
добавляет краулер, не заполняет и не перезаписывает контакты. Email из текста
страницы не считается автоматически проверенным контактом.

## Проверка и безопасный ручной запуск

Из корня checkout:

```bash
/home/golkonst/src/LexRadar/.venv/bin/python -m pytest -q tests/test_control_analysis.py tests/test_control_center.py tests/test_control_workflow.py tests/test_control_parser.py tests/test_control_leads.py
python3 -m py_compile control_analysis.py control_analysis_runner.py control_jobs.py control_pages.py control_center.py tests/test_control_analysis.py
git diff --check
```

Тесты используют подменённый анализатор и временные каталоги. Проверка реального
сетевого транспорта подменяет DNS и HTTP, сокеты не открываются. Реальный
сетевой сбор и наличие пригодного PDF в текущей среде не проверялись.

Действующий сервер при разработке не перезапускался. Для ручной проверки:

1. Дождаться завершения действующих заданий панели, особенно Parser (до 4 часов).
   Проверить `/jobs`; не останавливать панель посреди нужного сбора.
2. Остановить именно процесс панели штатным Ctrl+C в его терминале или через
   его существующий менеджер запуска. Не использовать `pkill`, не удалять state-dir.
   Если панель была запущена менеджером — обновить её тем же менеджером с прежними
   аргументами. Для ручного запуска с типовыми существующими каталогами:

   ```bash
   cd /home/golkonst/src/LexRadar-web-control
   /home/golkonst/src/LexRadar/.venv/bin/python -B control_center.py --parser-dir /home/golkonst/lexradar-data --results-dir /home/golkonst/src/LexRadar-compact --port 8080
   ```

3. Открыть `http://127.0.0.1:8080/organizations`, обновить страницу после рестарта
   (новый CSRF). Найти «Клиника А», убедиться, что в официальном сайте указан
   `https://aclinic-krd.ru`. Если записи нет — импортировать корректный Parser CSV
   существующим способом, не подменять код или состояние.
4. Нажать «Анализ» именно этой строки: это проба N=1. Проверить домен и параметры,
   затем поставить один чекбокс и запустить. Проверить X/Y, лог и review/PDF,
   если они созданы. Отсутствие автоматически добавленного email ожидаемо:
   адрес `klinika.aa@yandex.ru` сверять вручную на официальном сайте; в продукте
   тестовые значения не зашиты.
5. Только после проверки одного сайта выбрать «Следующие N» = 10. Проверить
   фактический список и пропуски перед подтверждением. Убедиться, что завершённый
   домен исключён, одновременно выполняется один сайт, ошибка сайта не прерывает
   следующие, отмена работает.

Эти шаги не запускались автоматически. Публикации и отправки писем нет.
