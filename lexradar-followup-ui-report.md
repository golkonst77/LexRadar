# Контроль после отправки: компактный интерфейс

Дата: 04.11.2026. Изменения подготовлены в рабочем дереве; commit/push не выполнялись.

## Результат

Вместо длинных карточек — таблица: организация и компактные ссылки на сайт/CRM/письмо/КП,
телефон, отправка, контроль, категория и операторский статус, «Открыть».
Четыре компактных показателя расположены в порядке «Пора проверить», «Ожидают срока»,
«Отложены», «Завершены». Строки идут в том же порядке; внутри категории — по дате
контроля от ранней к поздней. Смысл категорий и расчёт дат не менялись.

Просроченные строки выделены спокойным голубым фоном. Поиск и фильтр категории
работают в браузере, без запросов на каждую клавишу. Поиск учитывает название, домен
и телефон; номер можно вводить без скобок/пробелов/дефисов. Есть счётчик совпадений,
сброс и сообщение при пустом результате. Все 45–200 строк остаются в одной таблице:
пагинация не добавлена, чтобы не скрывать часть подходящих организаций.
На узком экране таблица прокручивается горизонтально; показатели переходят в два столбца.
CSS ограничен `#followup`, оформление других страниц не менялось.

«Открыть» делает GET `/followup?email=<ID>#followup-detail`: на странице ровно одна
панель выбранной записи и одна форма действия. Фильтры сохраняются при открытии
и возврате к списку. Панель показывает полное название, статус, даты, телефон,
ссылки, комментарий и раскрываемую историю `events` данной Email/Account пары.
Есть «Сохранить», явное подтверждение и «Отмена / к списку».
Без JavaScript таблица и открытие/сохранение работают, быстрые фильтры скрыты.

POST `/followup/action` и имена полей сохранены. После успешного сохранения сервер
возвращает 303 к той же записи; сообщение отображается при совпадении сохранённой
revision. Ошибка содержит ссылку обратно к выбранной записи. Неуспешный POST
не показывает успех. После POST фильтр сбрасывается, выбранная запись остаётся открытой.
Дата для deferred обязательна на сервере и дополнительно в браузере. no_answer
без даты по-прежнему назначает три рабочих дня. Предупреждение о do_not_contact
видно у формы; отказ всей организации по-прежнему блокирует дальнейшие изменения.

Вверху показано время последней успешной проверки **записи** CRM из checked_at;
при смешанном по времени снимке — также самая ранняя проверка. Это не утверждение
о полной успешной синхронизации всей CRM. При пустом снимке время недоступно.
Предупреждения о неполноте и устаревшем снимке остаются видимыми.

## Телефоны: источник и ограничения

До изменения все 45 записей локального снимка имели пустой phone. Код уже читал
Account.phoneNumber. В веб-подготовке control_mvp.py phones не передаётся,
а crm_prepare создаёт Account с пустым списком телефонов: это объясняет, почему
веб-экспорт сам по себе не гарантирует номер в CRM. Эти пути не менялись.
Точное текущее содержимое полей CRM подтвердить нельзя: единственный read-only
GET Account через прежний espo_export.API завершился недоступностью среды.
Запрос не печатал контакты или ключ. Нельзя обещать появление номеров у всех 45 строк.

Теперь берётся пригодный Account.phoneNumber, а при его отсутствии/непригодности —
пригодный phoneNumberData[].phoneNumber, сначала primary; элементы массива с
invalid/optOut пропускаются. Это поля, уже документированные и используемые
существующим экспортёром. Никаких придуманных полей, чтения телефонов из description,
поиска других организаций или записи Account нет.

Account используется только после подтверждения полного Email: Sent/dateSent,
parentType=Account и parentId, совпадающего с сохранённой привязкой из журнала;
возвращённый Account.id также проверяется. Account кешируется по ID внутри read_sent,
затем телефон сохраняется в прежнем read-only снимке. Дополнительных запросов ради
телефона нет. Прежние пределы: 200 GET, 1000 Sent, 8 секунд между началами запросов
плюс до 15 секунд последнего запроса; кеш проверки 60 секунд. Чтение остаётся
синхронным и при сетевом таймауте может занять это время. Фоновых задач не добавлено.

Без пригодного номера — «—». Для tel допускаются только 5–15 ASCII-цифр с
необязательным начальным плюсом после удаления пробелов, скобок, точек и дефисов.
Схема/добавочный номер/опасные символы не допускаются. При недоступности CRM —
предупреждение и прежний подтверждённый снимок, включая прежний телефон, если был.
После успешного чтения актуально отсутствующий номер не выдумывается и не подменяется.

## Как пользоваться и что проверить вручную

После **ручного штатного перезапуска существующего control_mvp.py оператором**
открыть /followup. Работающий процесс эти изменения ещё не применил. Не запускать
второй сервер и не перезапускать неизвестный systemd unit: прежний отчёт описывает
несовпадение unit с фактической точкой входа. Команды управления сервисом здесь
не выполнялись; фоновый компонент рассылки остаётся частью прежнего процесса.

1. Проверить 45 строк и четыре показателя, просроченные сверху, даты МСК.
2. Ввести название, домен или часть телефона, выбрать категорию; сбросить фильтр.
3. Нажать «Открыть»: проверить одну панель, полное название, ссылки и историю.
   «Отмена / к списку» возвращает к строке. На узком экране проверить прокрутку,
   видимость кнопок и клавиатурный фокус.
4. Отдельно сверить обе прежние отсрочки: 09.11.2026 10:00 МСК. Данные при разработке
   не менялись. Реальное сохранение проверять только осознанным действием оператора.
5. При доступной CRM сверить номер с соответствующим Account; для пустого номера
   ожидается «—». Если CRM недоступна, должно быть видимое предупреждение.
6. В форме проверить обязательную дату отсрочки, явное подтверждение, успешный
   возврат к той же записи; при устаревшей форме — отказ без ложного успеха.
