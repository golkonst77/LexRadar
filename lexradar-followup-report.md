## 1. Реализовано и недоступно

четыре счётчика, сроки, карточки организаций, ручные результаты и комментарии.

автоматических повторов нет. Дата отсрочки — выбранный день в 10:00 МСК.

данные живой CRM этим запуском не подтверждены. При недоступности интерфейс
показывает предупреждение, при наличии прежнего проверенного снимка — его
данные с датой проверки и предупреждением об устаревании. При первом запуске
без доступа реальных строк не будет. Фиктивных отправок нет.

## 3. Источник и достоверность привязок

Используется прежний `src.lexradar.espo_export.API`, включая его загрузку ключа,
запрет редиректов и таймаут. Новый CRM-клиент не создан. Путь чтения вызывает
только `request('GET', ...)`, не импортирует и не вызывает почтовый цикл.
Пагинация эквивалентна `control_mailing.all_rows`, но ограничена:
до 1000 Sent страницами по 200, до 200 запросов, до 8 секунд между началами
запросов плюс максимум 15 секунд последнего запроса. Кеш — 60 секунд.
Достижение лимита, повтор страницы, сетевые ошибки и неполнота явно обозначаются.
При большой истории старые первые 1000 Sent могут не включать новые отправки:
такой результат всегда помечен неполным; потребуется курсор/другой диапазон.

Принадлежность кампании — точные `steps.email.id` и `account_id` из штатных
`~/.local/state/lexradar/crm-prepare.json` и `espo-export.json`, прочитанных под
shared nonblocking flock. Поиск по теме или общему Account не используется.
Недоступные, повреждённые и конфликтующие привязки исключаются. Ручные старые
партии без записей в этих журналах не включаются; это ограничение полноты.

После списка читается полная карточка Email: обязательны `Sent`, валидный
небудущий `dateSent`, `parentType=Account` и точный `parentId` из журнала.
Пустые/некорректные даты исключаются. UTC источника преобразуется в offset-aware
время; `sendAt`, Draft и очередь не используются как доказательство отправки.
Account читается отдельно. Сохраняются Email/Account ID, фактическая дата UTC,
имя, телефон/сайт при наличии, время проверки. CRM-ссылки строятся только из
проверенных ID и фиксированной базы API.

КП: сохранённые Document ID, SHA-256, sourceId и attachment ID должны образовать
согласованный binding; точное вложение должно быть в Email, Document.fileId
должен совпасть с sourceId, полный список связей Document должен содержать
единственный нужный Account. Иначе ссылка скрыта. Ссылка ведёт на Document CRM;
локальный текущий PDF не подставляется. Байты PDF повторно не скачиваются:
неизменность текущего содержимого файла этой страницей не аттестуется.

## 4. Применение после ручного перезапуска

Открывать `http://127.0.0.1:8080/followup` после следующего штатного запуска
`control_mvp.py`. Работающий процесс автоматически новые импорты не подхватит.
Если доступ обычно организован через SSH-туннель, использовать прежний туннель.

Видимый `/etc/systemd/system/lexradar-web.service` запускает старый
`control_center.py`, где нет этой страницы. Перезапуск такого unit сам по себе
не подключит новый Control Center. Unit в этой задаче не изменён. Безопасная
команда остановки именно активного процесса здесь не установлена, PID не угадан.

Для ручного запуска в терминале после штатного завершения прежнего процесса
оператором (Ctrl+C в его терминале), из корня проекта применима существующая команда:

```bash
python3 control_mvp.py --parser-dir /home/golkonst/lexradar-data --results-dir /home/golkonst/src/LexRadar-compact --port 8080
```

Не запускать второй сервер на занятом порту. Команда здесь не выполнялась.
Это прежняя точка входа и она по-прежнему запускает существующий фоновый компонент
рассылки; его разрешения, график и поведение этой задачей не менялись.

## 5. Хранение и проверки безопасности

Данные — `.control-center-state/followup.sqlite3` (вне Git, файл 0600).
SQLite-транзакции сохраняют снимок, действия, историю и отказы; `BEGIN IMMEDIATE`
и версия записи предотвращают повторное/конкурирующее нажатие старой формы.
Частичное чтение сохраняет прежние наблюдения с явным предупреждением; новый
полный успешный пустой ответ очищает только снимок. Подтверждённое изменение
статуса/привязки или неверная дата удаляет соответствующее старое наблюдение.
Действия и отказы при этом не удаляются. GET не создаёт операторских действий.
Повреждение/ошибка записи не вызывает сброса данных; интерфейс сообщает ошибку.

POST использует существующие Host, Origin, CSRF и явное подтверждение; проверяются
размер/тип тела, повтор полей, ID, статус, даты и комментарий до 2000 символов.
SQL параметризован, HTML экранируется, произвольных путей нет, для сайта разрешены
только http/https без credentials. Отказ нельзя отменить случайным новым действием.
Локальный отказ не изменяет CRM и не останавливает рассылку: перед любым другим
контактом оператор обязан сверить и отдельно учесть отказ в соответствующем процессе.

  московским временем; переходы через UTC/МСК, offset-aware и неверные даты.
- GET-only Fake API: пагинация 201 записи, повтор страницы, пустой ответ,

## 6. Ответы, доставка и контакты

Однозначного подключённого read-only источника ответов/bounce для этого пути нет.
Автоматическая проверка не заявляется. Перед контактом нужна ручная сверка
входящих, ошибок доставки, отказов и основания контакта. Sent доказывает
зафиксированную CRM отправку, а не доставку. Задача не даёт разрешения на рекламный
звонок. Решение принимает оператор. Праздники пока не учитываются.
